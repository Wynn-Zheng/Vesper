## 1. 环境

### 1.1 必须有

| 项 | 要求 | 说明 |
|---|---|---|
| **Node** | **>= 22.6** | 低于这个版本**跑不了**（原生 type-stripping 是 22.6 才有的） |
| **npm** | 任意 | 只装两个运行时依赖 |

```powershell
node --version        # 必须 v22.6+（当前开发机 v24.20.0）
```

### 1.2 依赖只有两个

```json
{ "dependencies": { "ws": "...", "yaml": "..." } }
```

**加新运行时依赖之前先想清楚**：这个项目的卖点之一是"轻"。
能用 Node 内置 API 解决的（`node:fs` / `node:path` / `node:crypto` / `fetch`）就别引包。

**devDependencies** 只有 `@types/node` / `@types/ws` / `typescript`。

### 1.3 没有 lint / formatter

**只有 `tsconfig.json` 把关**：

```json
{
  "strict": true,
  "noUncheckedIndexedAccess": true   // 数组/对象下标访问返回 T | undefined
}
```

**所以要注意**：
- 数组下标一律 `arr[i]!`（你确信存在）或者判空
- 对象属性一律 `obj.key` 可能 undefined，要么 `??` 兜底，要么判空

**改完必跑**：

```powershell
node node_modules/typescript/bin/tsc --noEmit --noUnusedLocals
```

`--noUnusedLocals` 会揪出没用的变量和 import（这个项目经常靠它抓漏）。

### 1.4 TypeScript 硬约束（踩过，会直接报错）

| 禁止 | 原因 | 替代 |
|---|---|---|
| `enum` | type-stripping 不支持 | `const X = {...} as const` + `type X = typeof X[keyof typeof X]` |
| `namespace` | 同上 | 拆文件 |
| 构造函数参数属性 `constructor(private x: T)` | 同上 | 显式声明字段 + 赋值 |
| 相对 import 不带 `.ts` | 原生 ESM 找不到 | 一律写 `./foo.ts` |

## 2. 代码规范

### 2.1 注释

**这个项目的注释密度是刻意的**，不是啰嗦。规则：

- **写"为什么"，不写"是什么"**
- **踩过坑的地方必须写坑**（格式：现象 → 原因 → 解法）
- **有依据的地方引文献**（比如 `依据：Wixted & Ebbesen (1991)…`）

**示例**（`src/scheduler/distiller.ts` 的真实注释）：

```ts
// 游标推进到这批**最后一条消息的时间**，不是 Date.now()。
// 用 Date.now() 会把整理过程中新到的消息一起跳过（分组时 ts <= cutoff 被过滤掉）。
```

**反例**（修之前的 `src/loop/compress.ts`）：

```ts
/**
 * 超长时优先完整保留新摘要……让旧摘要从尾部让位；
 */
```

注释写"从尾部让位"，代码实际截的也是尾部——**注释和代码一致地错了**，看着没问题，跑起来中间的段落永久消失。
现在这段已经换成 `truncateTail()`，注释也重写了。**写注释时顺手对一眼代码在干什么。**

### 2.2 错误处理

**三层策略**：

| 场景 | 做法 |
|---|---|
| **用户输入错**（缺参数、格式不对） | 抛中文错误，HTTP 层映射成 400 |
| **外部故障**（API 超时、网络） | `warnAt` 记日志 + **返回降级结果**，不抛 |
| **内部 bug**（不该发生的） | 让它抛，让上层兜 |

**`warnAt` 的用法**（`src/core/log.ts`）：

```ts
warnAt('整理的模型调用失败，这轮跳过', { scope: opts.scope, err: String(err).slice(0, 80) })
```

**日志要能定位问题** —— 带上 `scope` / `personId` / 文件路径。

### 2.3 命名

- **中文标识符**直接用（`每轮最多条数`、`引用频率`）—— 因为这些是**配置项**，用户直接看 `rules.yaml`
- **代码内部变量用英文**，除非是"配置直通"（如 `rules.上下文压缩.摘要阈值`）
- **函数名说清动作**：`loadXxx` 读、`saveXxx` 写、`renderXxx` 渲染成文本、`ensureXxx` 保证存在

### 2.4 文件组织

| 放哪 | 什么 |
|---|---|
| `src/core/` | 基础设施（配置、日志、权限、路径、文本） |
| `src/channel/` | 协议层（收发消息） |
| `src/loop/` | 一轮对话的逻辑 |
| `src/memory/` | 记忆存取 |
| `src/self/` | 自我认知 |
| `src/console/` | **控制台后端 API**（一个页面一个 `*-api.ts`） |
| `console/` | **控制台前端**（HTML + 浏览器 JS） |
| `scripts/` | 测试脚本和工具（**不要建 `tests/` 目录**） |
| `docs/` | 文档 |

**规则**：`console/` 只放前端，**不要把后端逻辑写进去**。

## 3. 常见开发任务

### R1. 加一个模型可调的工具

**文件**：新建 `src/tools/<名字>.ts`

**模板**：

```ts
import type { Tool } from './types.ts'

export const myTool: Tool = {
  name: 'my_tool',
  // description 决定模型什么时候用它 —— 写清"该用"和"不该用"
  description: '做某件事。只在……时用，不要为了……而用。',
  parameters: {
    type: 'object',
    properties: {
      arg: { type: 'string', description: '参数说明（模型看这个）' },
    },
    required: ['arg'],
  },
  async run(args, ctx) {
    const arg = String(args['arg'] ?? '').trim()
    if (!arg) return JSON.stringify({ ok: false, error: '缺少 arg' })   // 失败也返回 JSON，别抛
    try {
      // ... 干活
      return JSON.stringify({ ok: true, result: '...' })
    } catch (e) {
      return JSON.stringify({ ok: false, error: e instanceof Error ? e.message : String(e) })
    }
  },
}
```

**注册**：`src/index.ts` 里 `registry.register(myTool)`

**验证**：
1. `npm start`，看启动日志的工具数（会 +1）
2. 控制台 →「对话 → 工具连通性」如果它该出现在那儿，还要改 `src/console/test-api.ts` 的 `TESTABLE` 数组和 `runToolTest` 的 switch

**注意**：
- **返回值必须是字符串**（会作为工具结果塞回模型）
- **失败不要抛**，返回 `{ok:false, error}`，让模型自己决定怎么办
- **有副作用的工具**（改文件、发消息）description 里要写清后果
- **工具不能绕过权限**：工具内部要做的事（发消息、改文件、操作桌面）都得再过一遍 `src/core/access.ts` 的 `checkAccess`，不能因为"是模型调的"就跳过
- **description 写"什么时候用"，不是"能干什么"**：模型是靠 description 判断该不该调的

### R2. 加一个控制台 API

**文件**：`src/console/<页面>-api.ts`

**看现有的分工**：
- `server.ts` —— 路由入口，按 `path` 分发
- `misc-api.ts` —— NapCat、余额
- `settings-api.ts` —— 设置页（数据、模型、版本）
- `people-api.ts` —— 成员页
- `test-api.ts` —— 测试页
- `plugin-api.ts` —— 插件页

**加一个 GET**：

```ts
if (method === 'GET' && path === '/api/xxx') {
  json(res, 200, { data: ... })
  return true
}
```

**加一个 POST/PUT**（要读 body）：

```ts
if (method === 'PUT' && path === '/api/xxx') {
  const body = JSON.parse((await readBody(req)) || '{}') as { id?: string }
  if (!body.id) { json(res, 400, { error: '缺少 id' }); return true }
  ...
  json(res, 200, { ok: true })
  return true
}
```

**验证**（不用开浏览器）：

```powershell
$h = @{'x-console-token'='<你的16位token>'}
(Invoke-WebRequest -Uri 'http://127.0.0.1:7788/api/xxx' -Headers $h -UseBasicParsing -TimeoutSec 10).Content
```

**注意**：
- **`return true` 表示已处理**；没匹配到要 `return false` 让上层继续
- **鉴权是统一做的**（`server.ts` 里），不用每个接口自己查 token
- **用户输入错给 400，内部故障给 500**（`server.ts` 的 catch 里有正则判断哪些算"输入错误"）

### R5. 改记忆策略（加一个字段）

**这是最容易出错的地方**（踩过多次）。

**加字段的安全流程**：

1. **接口加可选字段**（不要加必填）

```ts
export interface PersonFact {
  text: string
  // 新字段一律可选 + 有默认语义
  by?: 'it' | 'me'
}
```

2. **解析函数兼容老格式**

`src/memory/facts.ts` 的 `parseFactLine` 用正则匹配行格式。加字段时要写成**可选捕获组**：

```ts
const m = /^-\s+(.+?)（(\d{4}-\d{2}-\d{2})，置信\s*([\d.]+)(?:，([^）]*))?）(?:\｜(.*))?\s*$/.exec(line)
//                                          ↑ 可选                ↑ 可选
```

3. **序列化函数写新格式**，但**读的时候能读老的**

4. **写测试**（老格式 + 新格式 + 往返）

**参考** `scripts/test-people-extras.ts` 的第 3 节：老格式能读、by 为空。

**绝对不能做的**：
- **改解析正则让它只认新格式** → 老数据全丢
- **在 `saveXxx` 里重建整个文件而不先验证解析** → 解析错会覆盖老数据

**项目里已有的保护**（`facts.ts` 的 `appendFacts`）：

```ts
// 重写前先确认解析没丢东西。解析错了会把老数据覆盖掉。所以宁可不写。
const rawDashes = (existing.match(/^-\s+/gm) ?? []).length
if (parsed.length < rawDashes) {
  warnAt('facts 解析条数少于原文行数，拒绝重写（怕丢数据）', ...)
  return
}
```

**加新存储文件时也照这个模式做**。

### R6. 加一个定时任务

**文件**：`src/scheduler/` 下新建，参考 `distiller.ts` / `reflect.ts`

**模板**：

```ts
export interface MyTaskOptions {
  llm?: LlmOptions
  intervalMs?: number
}

export function startMyTask(opts: MyTaskOptions): () => void {
  const interval = opts.intervalMs ?? 30 * 60_000
  let stopped = false

  const run = async (): Promise<void> => {
    if (stopped) return
    try {
      // ... 干活
    } catch (e) {
      // 定时任务不能抛：一次失败不该让整轮挂掉
      warnAt('XX 任务失败', { err: String(e).slice(0, 100) })
    }
  }

  void run()                                    // 启动先跑一次
  const timer = setInterval(() => void run(), interval)
  timer.unref?.()                               // 别阻止进程退出

  return () => { stopped = true; clearInterval(timer) }
}
```

**注册**：`src/index.ts` 里 `startMyTask({...})` + 一行 `info('XX 已启动（每 N 分钟）')`

**关键**：
- **用游标记录进度**（参考 `distiller.ts` 的 `.state.json`），别每次全量重处理
- **失败时不要推进游标**：`distill()` 返回 `ok`，`!ok` 就 `continue`，游标不动、下次重试。
  这就是交接文档 §5.1 的问题，已经修好了，新任务照这个模式写
- **`timer.unref()`** 否则 Ctrl+C 退不掉

### R7. 加一项测试

**文件**：`scripts/test-<名字>.ts`

**模板**：

```ts
/**
 * XXX 的行为测试。
 */
let pass = 0
let fail = 0
function check(name: string, ok: boolean, extra = ''): void {
  if (ok) { pass++; console.log(`✓ ${name}`) }
  else { fail++; console.log(`✗ ${name}${extra ? '  ' + extra : ''}`) }
}

// ... 测试

console.log(`\n通过 ${pass} / 失败 ${fail}`)
if (fail > 0) process.exit(1)   // ← 必须，否则 check-all 判不出失败
```

**接入 `check-all`**（`scripts/check-all.ts`）：

```ts
{ name: 'XXX', cmd: 'node --env-file-if-exists=.env scripts/test-xxx.ts', expect: /通过 \d+ \/ 失败 0/ },
```

**注意**：
- **`expect` 正则必须匹配"全过"的输出**，`失败 0`
- **不要在 `scripts/` 里用 `chdir` 后不回来**（Windows 删不掉临时目录）
- **测试不能污染真实数据**：用 `setMemoryRoot` / `setPeopleRoot` / `setSelfFiles` 指向临时目录

## 5. 踩坑（开发时最常撞的）

> 完整清单见 `docs/交接文档.md` §7。这里只列**你几乎一定会撞**的。

### 5.1 PowerShell 会吞你的引号和中文

**症状**：`node -e "..."` 里带中文、`$`、`\`、正则，报各种语法错。

**规则**：**绝对不要用 `node -e` 跑带复杂字符串的代码**。

**正确做法**：

```powershell
# 1. 用 write 工具创建 scripts/_tmp.ts
# 2. node scripts/_tmp.ts
# 3. 删掉
```

**另外**：`$pid` 是 PowerShell 只读变量，别用它存自己的数据。

### 5.2 多行字符串传给 `.cmd` 会被截断

**症状**：带多行字符串传给外部 CLI（`.cmd`/`.bat`）时，对方只收到第一行。

**解法**：写文件，用 `--import` 或文件参数。

### 5.3 编辑 6086 行的 `index.html`

**`edit` 工具经常锚点失败**（CRLF / 缩进 / 不可见字符）。

**正确做法**：写一个 `.ts` 脚本，用**行号 splice**：

```ts
const lines = readFileSync('console/index.html', 'utf8').split(/\r?\n/)
lines.splice(startIndex, count, ...newLines)
writeFileSync('console/index.html', lines.join('\n'), 'utf8')
```

**改完必做 HTML script 语法检查**（见 §3-R3）。

### 5.4 前端文件是 IIFE，新函数必须挂 window

`console/settings.js`、`console/test.js` 整个在 `;(function(){...})()` 里。

```js
function myFunc() { ... }
window.myFunc = myFunc    // ← 忘了这行，onclick 报 is not defined
```

**踩过两次**：`loadNapcatSettings`、`installAiDesktop`。

### 5.5 Electron 禁用 `window.prompt`

点了报 `prompt() is not supported`。用 `askText()`（`index.html` 里已有）。

### 5.6 服务没起来时，依赖服务的那几项会跳过

`check-all` 里标了 `live: true` 的项（API 边界、并发、插件端到端、插件边界）在服务没起来时直接记「跳过」，不算失败。

其余项都不需要真服务——「控制台边界」走的是脚本内自建的临时 HTTP，不是 `npm start` 起来的那个。

```powershell
npm start          # 想跑全套就先起服务
npm run check-all
```

### 5.7 偶发失败先重跑

「看图」「改口」偶发 `fetch failed`（网络抖动），重跑就好。

## 6. 数据结构演进（加字段怎么不破坏老数据）

**这个项目所有记忆都是人能读的文件**，所以改格式要特别小心。

**三步法**：

### 第 1 步：新字段设成可选

```ts
export interface Xxx {
  old: string
  new?: string      // 可选
}
```

### 第 2 步：解析兼容三种情况

```ts
function parseLine(line: string): Xxx | null {
  // 老格式：- 内容（2026-01-01，置信 0.9）
  // 新格式：- 内容（2026-01-01，置信 0.9，新字段）
  const m = /^-\s+(.+?)（([^）]*)）(?:（(.+?)）)?/.exec(line)
  ...
  return { old: m[1], new: m[3] }   // 没有就是 undefined
}
```

### 第 3 步：写之前验证解析

```ts
// 重写前先确认解析没丢东西
const rawCount = (existing.match(/^-\s+/gm) ?? []).length
if (parsed.length < rawCount) {
  warnAt('解析条数少于原文行数，拒绝重写', {...})
  return
}
```

**测试要覆盖**：老格式能读、新格式能读、往返不变、坏行跳过。

## 8. 性能注意事项

**这个项目的性能瓶颈都在文件 IO**（没有数据库）。

| 操作 | 复杂度 | 实测 |
|---|---|---|
| `loadEpisodes()` | O(所有 episode 文件)，**带 5 秒 TTL 缓存** | 2000 个约 88ms（未命中）；命中时只做浅拷贝 |
| `recentVisible(scope, n)` | O(往前读的天数 × 当天 raw) | 通常只读今天，凑够条数就停 |
| `loadFacts(personId)` | O(一个文件) | 快 |

**所以**：
- **`loadEpisodes()` 有 5 秒缓存**（`saveEpisode` / `deleteEpisode` 会立即失效），高频路径调它没那么伤了；但一次回复里还是别反复调
- **加缓存前先想失效策略**（文件会被外部改，缓存容易脏）。现在是"5 秒 TTL + 写失效"，手改文件最多 5 秒可见
- **如果要做批量操作，先测**：`performance.now()` 包一下
