# 手机端适配

> 2026-10-31 起。目标：手机浏览器打开控制台能正常用，不是"能显示"。

## 1. 边界

**做**：响应式布局、触控尺寸、表格变卡片、二维码免输 token。

**不做**：独立 App、PWA（除非以后有 HTTPS）、平板专门布局（768px 就走手机样式）。

**前提**：手机能连到服务。同 WiFi 下把 `CONSOLE_HOST` 设成 `0.0.0.0` 就行（已支持，详见 §7）。

## 2. 现状（实测）

### 2.1 断点几乎失效

`console/index.html` 里唯一一条移动端规则用的是**旧类名**：

```css
@media(max-width:768px){
  .sidebar{width:60px}     /* 实际标签是 <aside> */
  .main{padding:12px}      /* 实际标签是 <main> */
}
```

类名对不上 → **这条从没生效过**。所以真手机上侧栏还是 200px，内容区只剩 190px，文字竖排。

### 2.2 已有断点（有效）

| 选择器 | 断点 | 效果 |
|---|---|---|
| `.dash-hero` | 840px | 单列 |
| `.try-layout` | 1000px | 单列 |
| `.self-grid.cols2/.cols3` | 1100px | 单列 |
| `.self-status-grid` | 1100px | 单列 |
| `.state-top` | 900px | 单列 |
| `.hero` | 900px | 单列 |

这些是**按视口宽度**触发的，真手机打开会生效。所以大部分页面单列化是自动的。

### 2.3 修完主框架后只剩 3 个页面会溢出

把 `aside` 隐藏、`main` 占满 390px 后重测（模拟阶段 1 完成的样子）：

| 页面 | 溢出元素 | 原因 |
|---|---|---|
| `v-members`（成员） | 17 处，`TABLE:400` | 表格最小宽度 400px |
| `v-logs`（运行日志） | 40 处，`.m:372` | 日志消息不换行 |
| `v-try`（试聊） | 3 处，`.try-side:380` | 右侧面板固定 380px |

其余 11 页在 390px 全宽下已经没问题（靠 §2.2 那些断点）。

**2026-10-31 完成阶段 0/1/2 后复测：14 个页面全部 0 处溢出。**

## 3. 阶段 0：修坏规则 ✅ 已完成

**改**：`console/index.html` 里那条 768px 规则，`.sidebar` → `aside`，`.main` → `main`。

**验收**：

```js
// 浏览器 390px 宽
document.querySelector('aside').getBoundingClientRect().width  // ≈ 60
document.querySelector('main').getBoundingClientRect().width   // ≈ 330
```

**工作量**：10 分钟。做完手机能看，但不顺手。

## 4. 阶段 1：主框架 → 底部 tab ✅ 已完成

### 4.1 为什么是底部 tab 不是侧栏抽屉

- 拇指自然可达区在屏幕下半；顶部/左上要伸手
- 抽屉要点两下（打开 + 选中），tab 点一下
- 侧栏 200px 在 390px 屏上占一半，换成 56px 底栏只占高度

### 4.2 改法

```css
@media (max-width: 768px) {
  aside {
    position: fixed; bottom: 0; left: 0; right: 0;
    width: 100%; height: 56px;
    flex-direction: row; align-items: center;
    border-right: none; border-top: 1px solid var(--line);
    padding-bottom: env(safe-area-inset-bottom);   /* iPhone 刘海 */
    z-index: 100;
  }
  aside .brand { display: none; }
  #nav { flex-direction: row; justify-content: space-around; padding: 0; }
  #nav button { /* 图标上、字下，10px */ }
  main { padding-bottom: calc(56px + env(safe-area-inset-bottom)); }
  header { height: 40px; padding: 0 12px; }
  .views { padding: 12px; }
}
```

### 4.3 导航怎么排（待定，见 §8）

7 个导航项，底栏最多放 5 个。

### 4.4 验收

- 390px：底栏 5 项，点击能切页，当前项高亮
- iPhone 12/13/14（带 Home 条）：底栏不被遮挡
- 横屏（844×390）：底栏仍可用，不占太多高度
- 桌面（≥768px）：完全不受影响

**工作量**：半天

## 5. 阶段 2：三个页面专项 ✅ 已完成

### 5.1 成员页表格 → 卡片

```
现在（TABLE 最小 400px，手机上横向滚）
┌──────┬────────┬──────┬─────┐
│ 名字 │ QQ 号  │ 关系 │ 操作│
└──────┴────────┴──────┴─────┘

手机：
┌────────────────────────────┐
│ 小明                 [朋友] │
│ QQ 123456789               │
│ 12 条事实 · 3 段经历         │
│               [档案] [更多] │
└────────────────────────────┘
```

**两种做法**：

- **A. 纯 CSS**：`@media` 下 `table` 改 block，`thead` 隐藏，`td::before` 显示列名
  - 优点：不改 JS
  - 缺点：语义变差（表格还是表格），troubleshoot 时 DOM 和视觉对不上
- **B. JS 判断**：`members.js` 里窄屏时渲染卡片、宽屏渲染表格
  - 优点：结构干净
  - 缺点：两套渲染代码

**建议 A**（先简单，真难用再换 B）。

**验收**：390px 下成员列表无横向滚动，每人的名字/QQ/关系/操作都能看到。

**工作量**：半天

### 5.2 运行日志

```
现在：一行 [时间] [级别] [很长的消息]     → .m 宽 372px
手机：[时间] [级别]
      [消息换行]
```

**改法**：

```css
@media (max-width: 768px) {
  .log .line { flex-wrap: wrap; }
  .log .line .m { max-width: 100%; word-break: break-word; }
}
```

**验收**：日志页无横向滚动，消息完整可见。

**工作量**：2 小时

### 5.3 总览 / 试聊收尾

真手机上（视口 390）这两个已有断点会单列。只需要检查单列后：

- `.dash-mini`（137px 固定）会不会撑破
- `.try-side`（380px 固定）会不会撑破

**工作量**：2 小时

## 6. 阶段 3：细节打磨

| 项 | 为什么 | 改法 |
|---|---|---|
| 输入框字号 ≥ 16px | iOS Safari 小于 16px 会自动放大页面 | `.mt-input,.self-input{font-size:16px}` |
| 触控目标 ≥ 44px | `mini-btn` 只有 24px 高，手指点不准 | 手机端 `min-height:44px` |
| 底部安全区 | iPhone Home 条会盖住底栏 | `env(safe-area-inset-bottom)` |
| 长按菜单 | 长按会弹"复制/翻译" | `-webkit-touch-callout:none` |
| hover 粘住 | 手机上 `:hover` 点完不消失 | `@media (hover:hover)` 包住 |
| 滚动惯性 | 列表滚起来发涩 | `-webkit-overflow-scrolling:touch` |

**工作量**：半天

## 7. 连通（已完成）

`CONSOLE_HOST` 环境变量：

```ini
# .env
CONSOLE_HOST=0.0.0.0    # 默认 127.0.0.1，只有本机能连
```

**实测**：`netstat → 0.0.0.0:7788`，用局域网 IP `http://172.21.162.8:7788/?token=...` 打开，数据正常。

**注意**：

- 改成 `0.0.0.0` 后**同一 WiFi 里任何人都能访问**（能读记忆、能发消息），只在信得过的网络开
- Windows 第一次会弹防火墙提示，要点"允许"

**跨网络**（4G / 公司网）需要隧道或上云，不在本文范围。

## 8. 待定

### 8.1 底栏怎么排 ✅ 已定

```
仪表盘 / 对话 / 自我 / 成员 / 更多
```

「更多」里是：插件 / 日志 / 设置。

**为什么这么排**：
- **对话放第二个**——手机上最高频的操作是"跟它说句话"，不能排在后面
- **成员第四个**——看"它记住了谁"比管理插件常用
- **插件进「更多」**——装/卸插件是低频操作，且手机上操作插件本来就别扭

**实现方式**：用 CSS `order` 重排，**不改 HTML 顺序**——桌面侧栏还是原来的顺序（仪表盘/自我/插件/成员/日志/对话/设置）。

### 8.2 重页面做不做

成员表格、日志检索在手机上天生难用。

| 方案 | 说明 |
|---|---|
| **A** | 全做（表格改卡片） |
| B | 显示"建议用电脑打开" |
| C | 简化版（只显示前 20 条，没筛选） |

**建议 A**：成员页是"它记住了谁"的入口，手机上会想看。

### 8.3 平板（768-1024）

iPad 竖屏 768px 正好在断点上。**建议不管**，768px 就走手机布局。
