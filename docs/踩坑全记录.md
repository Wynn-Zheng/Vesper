## 一、记忆与压缩

### 1. 摘要该丢头部，不是尾部

**位置**：`src/loop/compress.ts:102`

```
原来：truncateSummary(prev, room)  ← 保留开头（最老），丢尾部（次新）
现在：truncateTail(prev, room)     ← 保留尾部（次新），从头部让位
```

**实测**（每段 150 字跑 6 轮）：

```
第 5 次后（400 字）留下: 第 1、2、3、5 段     ← 第 4 段丢了
第 6 次后（400 字）留下: 第 1、2、3、6 段     ← 第 5 段又丢了
```

**后果**：最老的 300 字永远在，中间段落永久消失，最新只留 100 字。

**教训**：**滚动摘要要"最近的优先"，不是"最早的优先"。**

---

### 2. 摘要不该重复拼旧版

**位置**：`src/loop/compress.ts:126`

```
模型输出已经包含旧摘要（prompt 里给了 prev），mergeSummary 又拼一次
→ 实测摘要开头是「他说最近工作压力很大…；他说最近工作压力很大…」
→ 白占一半预算
```

**现在的做法**：用 `sharedBigrams` 判断模型是否已经合并（`cover >= 0.05` 就认为合并了），不再重复拼。

**教训**：**给模型喂了旧摘要，就别再手工拼一遍** —— 要么让它合并，要么你自己合并，别两样都做。

### 3. 摘要上限 400 太小

**位置**：`src/loop/compress.ts:15`、`src/core/config.ts:325`

```
原来是 400 字 + 阈值 20 条 + 保留 6 条
→ 聊两小时的群，历史就被压成 400 字 + 6 条原文
现在：1500 字 + 阈值 40 条 + 保留 12 条
```

**教训**：**上限要按"人能不能记住"来定**，不是按"省 token"。

### 4. 整理失败不能推进游标

**位置**：`src/scheduler/distiller.ts:132`

```
原来的写法是无论成败都写 Date.now()
→ 一次限流/网络抖动就让那批消息永久消失
现在：失败不动游标，用 lastTs（最后一条消息时间）而不是 Date.now()
```

**教训**：**游标是"已处理到哪"，不是"上次跑的时间"。**

### 5. 游标用 `Date.now()` 会跳过整理期间的新消息

**位置**：`src/scheduler/distiller.ts:143`

```
state.scopes[scope] = Date.now()
→ 整理耗时期间到达的消息，ts < now，下次会被 t.ts <= cutoff 过滤掉
现在：state.scopes[scope] = lastTs（这批最后一条的时间）
```

### 9. 同一条事实换个说法，sim 只有 0.45

**位置**：`src/memory/distill.ts` 的 `factRelation`

```
实测：同一事实改写后 sim 只有 0.45，而「喜欢猫」vs「喜欢狗」有 0.50
→ 单靠相似度阈值区分不了"同一件事换个说法"和"真的不同"
现在：灰色地带（0.45~0.9）交给模型判断
```

**后来又踩的坑**：模型只回 yes/no 时，`no` 同时表示"两件不同的事"和"互相矛盾"，
代码只能一律塞进 `open` 问用户 → 无关的两件事也去打扰人，真矛盾反而只是并存。

**现在**：三分类 `same / different / contradict`

| 关系 | 处理 |
|---|---|
| same | 刷新确认日期，必要时补一条更详细的 |
| different | 两条并存，**不打扰用户** |
| contradict | 旧事实标 `supersededAt`（不再注入，文件里留着），新的写入，`open` 里留一句说明 |

**教训**：**二选一的判断，往往把一个维度压扁了** —— 先问"这个 no 到底包含几种情况"。

### 16. recall 读 3 天 raw 只用 8 条

**位置**：`src/memory/recall.ts:51`

```
原来是 recentRaw(3).filter(...).slice(-8)
→ 把三天所有会话的记录全读出来，只为取最后 8 条
```

### 18. 相似度对短句天然偏低

**位置**：`src/memory/recall.ts:266`、`src/core/text.ts:31`

```
实测数据：
「你那只猫豆豆还好吗」vs「他养过一只猫叫豆豆」  sim 0.143 / 共同 bigram 2  ← 相关
```

### 41. PowerShell 会把你的代码改坏

**症状**：`node -e "..."` 里带中文/`$`/`\`/正则 → 各种语法错。
**规则**：**永远用 `write` 写 `.ts` 脚本再跑**。

### 42. `$pid` 是只读变量

赋值失败 → 变成进程 ID → 后续路径全错。

### 43. 多行字符串传给 `.cmd` 会被截断

外部 CLI 只收到第一行 → 后续拆解/参数全跑偏。
**解法**：写文件 + `--import`（或任何"读文件"的参数）。

### 44. 大文件 `edit` 锚点失败

6086 行的 `index.html`，`edit` 经常 "old_string not found"（CRLF / 缩进）。
**解法**：行号 splice + 改完做 HTML script 语法检查。

### 45. 删 `const X = [...]` 只删到第一个 `]`

**踩过**：SELF_TABS 留了 6 行残骸，语法错。

### 46. 前端是 IIFE，新函数必须挂 window

### 47. Electron 禁用 `window.prompt`

### 48. `git add -A` 会把别人的改动也提交

## 八、主动消息与关系（2026-10-28 补）

### 51. "关系不好就不主动"会死锁

**位置**：`src/scheduler/proactive.ts`

```
原来的阶段表：陌生 → dailyMax = 0（永不主动）
关系衰减：7 天不说话开始扣，一路能扣到 0 → 掉回陌生
→ 于是：冷淡 → 不主动 → 更冷淡 → 永远不主动
```

**现在**：每个阶段都能主动，只是门槛/间隔不同（陌生：30 天一次 + 由头 ≥7）。
主动与否由**由头分**决定（有没有具体的事想说），关系只决定"多容易开口"。

**依据**：Roberts & Dunbar (2015)——冷掉的关系里只有 6.7% 能回到内层，
说明"等它自己热起来"是不现实的，得主动维护。

**教训**：**任何"某条件下永久关闭"的开关，都要检查它会不会被另一个机制推入这个条件。**

### 52. 配置写了一行，代码另写一份

**位置**：`proactive.ts` vs `rules.yaml`

```
rules.yaml 里：行为.主动消息.每日上限: 由阶段决定
proactive.ts 里：写死一张按阶段的表（minGapHours/dailyMax）
→ 用户把每日上限改成 1 或 0 完全无效；stage 的「主动: 三五天一次」也从来没被读过
```

**现在**：`StageRule` 加了 `主动间隔小时 / 每日上限 / 最小由头` 三个结构化字段，
以 `rules.yaml` 为准；`每日上限` 填数字时作为全局硬上限。`主动` 那句只给人看。

**教训**：**注释/文案/配置里的"说明"，如果代码不读，过一阵就会变成谎话。**
要么让它被读，要么删掉。

```
原来：亲近 → "昵称"，亲密 → "专属"
prompt：'你叫他「昵称」'
→ 模型真的会叫你"昵称"
```

**现在**：`称呼` 写的是**怎么叫**（"叫名字里的一两个字"/"用你们之间习惯的叫法"），
并且优先用 `rules.yaml` 的 `关系.昵称`。群聊里不渲染称呼。

**教训**：**配置里的值如果会被原样插进 prompt，它必须是一句"指令"，不能是一个"占位符"。**

### 55. 两个"多久"互相打架

**位置**：`proactive.ts` 的主动间隔 vs `decay.ts` 的衰减容忍期

```
主动间隔：陌生 30 天、眼熟 14 天
衰减容忍：7 天
→ 按它的节奏去联系，关系早就掉了；等于"联系得越准时，掉得越稳定"
```

**现在**：容忍期 = `max(阶段基础值, 主动间隔 × 1.3)`，从同一张表派生。

**教训**：**任何两个描述"时间节奏"的参数，先检查它们是不是同一个系统的两面。**
分开配就会互相打架，而且测试不会报错——两边各自都"正常"。

## 九、一条通用规律

看完这 55 条，能归纳出这个项目最常犯的四类错误：

### 1. 用"能存下来"代替"能被想起来"

- 摘要只留最早的（该留最新的）
- 事实只 append（该去重）
- insights 只增（该判重）

### 2. 用"简化"代替"正确"

- 群聊不吃 facts（"分不清谁的" → 加 who 字段就好了）
- importance 用 1-10（模型分不出来 → 二选一）
- 相似度当唯一判据（短句召回率低 → 加 bigram）

### 3. 失败路径没设计

- 整理失败推进游标（→ 丢数据）
- 解析失败直接重写（→ 覆盖老数据）
- 模型输出不是 JSON（→ 要有 `\{[\s\S]*\}` 兜底）

### 4. 假设数据分布

- 假设模型会给 importance 打高分（实际全 2-3）
- 假设群名单总是一样的（实际会返回 1 人）
- 假设名字唯一（实际会重名）

**所以改代码前，先问三个问题**：

1. **这条数据"什么时候会被想起来"？** 不是"怎么存"。
2. **失败了会怎样？** 有没有人知道失败了？
3. **真实数据长什么样？** 去统计，别假设。

## 十、群聊（2026-11 审查后的新增）

> 这一节的共同特征：**都在"多人、异步、有上下文"的场景下才暴露**，
> 单聊或一次性测试完全看不出来。完整行为契约见 `docs/群聊行为.md`。

### 56. 合批后整段只挂最后一个人的名字

**位置**：`src/boot.ts` 的 `batchLines` / `flush`

```
原来：texts.join('\n')，然后用 buf.last 的名字冠一次前缀
实测：formatUserText('group:1','小明','小红的话\n小明的话')
      → "小明：小红的话\n小明的话"   ← 小红的话被记成小明说的
现在：一批超过 1 条就逐条拆 {name,text}，只给 prompt 用；判定仍用原始文本
```

**两条关键约束**：

1. 判据是**条数**，不是"不同名字数"——QQ 同群允许重名名片，按名字数会判成单人。
2. **同一个人连发也要逐条带名字**。只冠一次前缀的话，第二句在模型眼里
   就是"它自己刚说过的"（`people/group.ts` 明确告诉模型：无前缀 = 你自己的话）。

### 57. 名字写进调度层的 text，顺手污染了判定

**位置**：`src/boot.ts` 的 `flush`

名字拼进 `text` 之后，「嗯」「哦」这类短回复识别（整段锚定）、内容过滤、
回复预算全被带偏。所以：**判定用原始拼接文本，带名字的版本只走 prompt**。

### 58. 群里没叫它的消息不进 session，所以接不上前文

**位置**：`src/boot.ts` 的 `observeOnly` 出口、`src/loop/session.ts` 的 `pushHeard`

```
原来：observeOnly 直接 return，pushTurn 只在 chat.ts 做
     → 群里的其他对话从来没进过上下文，"刚才聊啥呢"它完全不知道
现在：单独记进 Session.heard（12 条 / 2 小时），渲染成【群里刚才在聊】
```

**为什么单独存**：塞进 turns 的话，模型会以为自己参与了那些对话，
`compress.ts` 还会把它们压成「对方说」，几个人的身份在摘要里永久压平。

**记录点必须覆盖所有"决定不说话"的出口**，不能只挂在 observeOnly 上：
切到「自己判断」档时 observeOnly 恒为 false，那样它反而在最活跃的档里最失忆。

### 59. 引用回复被完全忽略

**位置**：`src/channel/onebot.ts` 的 `replyTargetId` / `isAddressed`

QQ 里最常见的追问就是"直接回复它那句、不 @"。原来 `reply` 段被丢弃，
于是永远不回。现在记住自己发过的消息 id（300 条）反查——reply 段只给消息 id、
不给发送人，没别的情报可用。

**只做正向判断**（引用我的 = 叫我），不做反向（引用别人的 = 别理）：
ownIds 是进程内存的，重启就空，反向判断会让"引用它昨天的消息"变成装没看见。

### 60. 连续对话窗口自证续期

**位置**：`src/channel/onebot.ts` 的 `markTalker` 调用点

```
原来：addressed 和 followUp 都调 markTalker
     → 一次 @ 换来两分钟内每句都必回且跳过打分，群里显得黏人
现在：只有真的被叫到才续期；followUp 只消费不续期
     另外，成功发出一条回复后也刷新锚点（锚在"它真说话"的时刻）
```

只锚 @ 的话，连聊三分钟会突然断掉；只锚"最后一条"的话，见第 66 条。

### 61. 旁听在"决定不说话"的出口漏记，开了开关就失忆

见第 58 条。补一句：**「已读不回」「偶尔不回」「退避」「打分没过」「限速」
这些出口都要记**，否则某个开关一开，那类消息就彻底消失。

### 62. 能力开关点完弹回原状（写了但读的是旧快照）

**位置**：`src/console/server.ts` 的 `freshRules`

```
原来：GET /api/ability 用 opts.getRules() —— 进程内存快照，靠 watchFile 1.5 秒轮询更新
现象：点开关 → 提示"已关" → 列表立刻弹回"开"（配置其实已经写进文件了）
现在：控制台里"显示用户刚改过的配置"的接口一律每次读文件
```

**教训**：「写进文件了」和「界面读得到」是两件事。存储层测试全绿，
不代表接口层没问题。

### 63. 新加的配置项在老安装上写不进去

**位置**：`src/console/config-write.ts` 的 `setConfigPath`

```
原因：新键的默认值在代码的 DEFAULTS 里，老用户的 rules.yaml 里没有那一行
     → "界面上有开关、点保存报找不到键"
修法：键不存在时往父级段落末尾补一行（缩进按同段实际缩进）
```

**两个边界**：父级是 YAML 列表时要拒绝（硬插会写出非法 YAML，
下次启动整份配置回落默认）；父级不存在时仍报错，不许凭空造段落。

**这条坑为什么难发现**：仓库里的 `rules.yaml` 有那一行，所以单测和门禁全绿；
只有对着**真实部署实例**发请求才暴露。

### 64. 非原子写（`writeFileSync`）在控制台里有 7 处

**位置**：`src/console/*.ts`

写到一半崩了就是半截文件。`rules.yaml` 半截 → 下次启动**静默**回落默认配置；
`.env` 半截 → 读不到 API Key → **静默**进回显模式，用户只看到"它不说话了"。
全部改成 `writeAtomic`，并加了守门测试（`test/atomic-writes.test.ts`）。

### 65. 定时任务会叠加跑

**位置**：`src/core/timer.ts` 的 `onceAtATime`，用在 distiller / proactive

setInterval 只判断"停没停"，不判断"上一轮跑完没有"。单次执行要调模型，
慢的时候会超过间隔：整理叠加 → 重复花钱 + 同一条事实提炼两遍；
主动消息叠加 → 同一个人连着收到两条"想你了"。

### 66. 合批后只给最后一个人续"刚聊过"的窗口

**位置**：`src/boot.ts` 的 `BatchInfo.senders`

一批里 9001、9002 都说了话，回复后只有 9002 被记为"刚跟它说过话"。
9001 接着说一句不 @ 的，会被判成"没叫它"→ 不回，像聊到一半突然不理人。
现在整批的 senders 逐个续期。

### 67. 发不出去的话仍留在历史里

**位置**：`src/boot.ts` 的 `sentNothing` 分支

`say()` 一条都没发出去（断线/被拒/内容被 stripMentions 清空）时，
历史里仍有一条 assistant。用户一个字没收到，它下一轮却"记得自己说过"，
会接着自己的话说、甚至引用用户没看见的内容。

**注意**：这条的修法不能再挂在"生成后限速"那条分支上——那条**不可达**
（同一会话被发送链串行化，`g:` 只有一个消费者），挂在上面等于没修。

### 68. 入口校验要和下游的**分类标准**一致

**位置**：`src/channel/onebot.ts` 的 `onEvent` 开头

```
原来：只挡"message_type === 'group' 且群号为空"
下游：不是 private 就当群
结果：discuss / guild / 缺 message_type 落在缝里 → 空群号
     → groupcache.dirOf('') 抛「群号不合法」→ 消息回调被打断
现在：不是 private 就必须有数字群号
```

**通用教训**：修入口校验时，先去读**下游是怎么分类的**，让准入标准和它对齐。

### 69. 提示指涉要指向真实存在、方向正确的段落

**位置**：`src/loop/prompt.ts`

踩过两次：先写【最近说过的话】（那段在 `chat.ts` 里被清空了，永远不存在），
改段名之后又说"上面"——而那段渲染在这句提示**下面**。
现在不提方向，只说"那段"。

### 70. 合批渲染会丢掉"@ 它那句"

**位置**：`src/loop/chat.ts` 的 `renderBatch`

只按"从新往旧装"的话，刷屏时第一条（通常就是"@它 你看这个"）会被挤掉，
模型看到一堆别人的长文，却不知道有人在叫它。
现在第一条先占位保住，丢了几条明写「（前面还有 N 条没贴出来）」。

### 71. 门禁自己会"假绿"

**位置**：`scripts/check-all.ts` + `scripts/gate.ts` + `scripts/audit-console.ts`

三种都真实发生过：

1. **服务没跑时，需要服务的检查被记成 `ok: true`** —— 最后照样打印"全部通过"，
   其实一个接口都没打过。
2. **审计脚本从不返回非零**，结尾那句 `✓ 关键函数都在` 还是无条件打印的 ——
   不管前面报了多少 ❌，这项永远"通过"。
3. **一个用例都没跑也算过**：`通过 0 / 失败 0` 能被 `expect` 正则可以匹配。

现在门禁有三道防线：跳过项单列、结论行 + 非零退出码、至少 1 项且 0 失败。
判定逻辑抽到 `scripts/gate.ts` 并单独测（11 条）。

**还有个自指的坑**：计数只看结尾 20 行。第一版拿整段输出匹配时，
单元测试里一条标题叫「通过 0 / 失败 0」的用例被当成结果，门禁当场判
"单元测试只跑了 0 项"——门禁把自己抓了。

### 72. 测试之间会通过"全局状态"互相污染

`--test-isolation=none` 下所有测试共用一个进程，踩过三次：

- **限流表**是模块级的，几个用例共用一个群号 → 后面的用例"一条都没发"
- **会话落盘**：`clearSessions()` 只清内存，`loadSession` 会把上一个用例的 heard 读回来
- **测试文件在导入时**就把路径改到自己的临时目录 → 别的文件的用例看到的是别人的数据

对策：每个用例用**独立群号**；改全局路径的用例在 `afterEach` 里还原
（`resetSelfFiles()`）；测试里读源码路径用 `import.meta.dirname` 拼绝对路径
（别的用例会 chdir）。

## 附：怎么自己发现新坑

```powershell
# 搜代码里所有"原来 / 实测 / 踩过"，就是全部已知坑
Get-ChildItem src -Recurse -Filter *.ts |
  Select-String -Pattern '原来|实测|踩过|之前是|以前是'
```

**加新坑时，也照这个格式写注释**：

```ts
// 原来：xxx（错的做法）
// 实测：xxx（具体数据）
// 现在：xxx（对的做法）
```

这样下一个人 grep 一下就能找到。
