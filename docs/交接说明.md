## 二、怎么跑

```bash
# 单元测试（注意 --test-isolation=none：单进程跑，全局状态会互相影响）
node --test --test-isolation=none --test-force-exit test/*.test.ts

# 全量检查（需要有一个后端在 7788 上跑，且 **token 要匹配**）
node --env-file=.env src/index.ts        # 另开一个窗口
node scripts/check-all.ts

# 打包 + 部署
node scripts/package-electron.ts
```

⚠ **端口 7788 只能有一个服务**。桌面版（`G:\bot\...`）和源码 `node src/index.ts`
的 token 不一样，同时开会让你以为"检查突然全红"。要跑 `check-all` 就先关桌面版。

启动桌面版有个怪癖：**必须用 `explorer.exe "G:\bot\Vesper-0.1.6-win-x64\Vesper.exe"`**，
直接执行会立刻退出。

## 三、群聊这块的"为什么这么写"

细节在 `docs/群聊行为.md`，这里只挑三条最容易改错的：

1. **参与方式是唯一权威**。`rules.yaml` 的 `GroupChatMode`（只听 / 熟人续话 /
   自己判断）决定"要不要 @它才回"。`access.yaml` 里那个 `成员.必须at` 是遗留字段，
   **已经不读了**。别把它加回去。
2. **旁听（Session.heard）和 turns 是两套东西**。群里没叫它的消息进 heard（12 条 /
   2 小时），不进 turns —— 进了 turns 它会以为自己说过那些话。
3. **出站一律去掉 @**。它只是群里的一员，没有点名权。想出站兜底见
   `src/channel/send.ts` 的 `stripMentions`。

## 四、改代码前必须知道的坑

按"踩了会浪费半天"排序：

| 坑 | 说明 |
|---|---|
| 单进程跑测试 | `--test-isolation=none`，所以**全局状态会串**。写过 rate-limit 表、持久化 session 的测试必须用独立的群号/目录，否则互相污染 |
| 门禁会假绿 | 门禁自己出过三次假绿：跳过记成通过 / 审计永不失败 / "通过 0 失败 0"。现在 `scripts/gate.ts` 会把跳过项列出来 |
| 非原子写 | 所有落盘都走 `writeAtomic`。新增写文件的地方**别直接 `writeFileSync`** |
| 提示词里的指涉 | 写过"上面【群里刚才在聊】"但那个块渲染在下面。指针要指向真实存在且方向正确的段落 |
| Windows 的 `child.kill()` | 是 `TerminateProcess`，收不到 SIGTERM。所以优雅退出这条路在 Windows 上是断的（见 `docs/插件安全与隔离.md` BUG3-11） |
| 插件 `files` 的根 | 是插件自己的 `dataDir`，不是项目根。越界和 junction 都会被 realpath 拦下 |

## 五、明确"不做"的

| 项 | 为什么不做 |
|---|---|
| 插件同步死循环隔离（BUG3-19） | 要子进程或 VM，等于重写插件 API 和所有插件的写法。而插件本来就是普通模块，能 `import` 任何东西 —— 没有真隔离就别假装有。已写进 `docs/插件安全与隔离.md` 当明示 |
| 第 4 档「只@接梗」 | 梗库目前只有词语子串匹配，撑不起这个模式 |
| 每条旁听都同步落盘（BUG-16） | 群里消息密度高时 I/O 放大明显，取舍是不落盘（重启后 heard 清空） |
| 真实群聊回归 | 需要真人的 QQ 号在真实群里收发。代码层面做不到 |

## 六、下一步最该做的事（只有一个）

**在真实群里用它几天。**

这是唯一还能发现新问题的地方。我这 20 多轮都是在验证"我想到的场景"，
真实群聊会给出"我没想到的场景"。具体怎么喂给我（或下一个接手的人）：

```
1. 群里两个人同时 @ 它 → 看它回一条还是两条、有没有张冠李戴
2. 问它"刚才聊啥呢" → 看它引用的旁听内容对不对、有没有编
3. 引用它的话但没 @ → 看它接不接
4. 切到「只听」→ 看它是不是真的一个字都不说
5. 让它答一个需要记忆的问题（"我上次说我喜欢什么"）→ 看记忆有没有串
```

出问题时抓这几样：`data/logs/当天.jsonl` 里那几条、当时的 `Session.heard`、
以及 `data/raw/` 里对应的原始对话。
