# 记忆的完整构成

> 2026-10-26
> 这份文档是对着代码写的：每条都标了实现文件，不是凭印象。

---

## 一、六层结构

从"最原始"到"最抽象"，一共六层：

```
raw（原始对话）          ← 每句话都记，7 天
  ↓ distill（提炼）
episode（情节）          ← 一件完整的事，带重要性/情绪
  ↓ distill（再提炼）
insight（洞察）          ← "我对他的一些看法"
  ↓
fact（事实）             ← 关于这个人的具体事实，带置信度/可见性
open（待问/答应）        ← 还没问完的、答应过的事
shared（共享）           ← 所有会话都看得见
```

### 1. raw（原始对话）

**文件**：`persona/memory/raw/2026-10-25.jsonl`

**实现**：`src/memory/store.ts` 的 `appendRaw()`

**每行长这样**：

```json
{"ts":1792923527588,"scope":"private:1234567890","role":"user","text":"在吗","senderId":"1234567890"}
```

**谁写它**：`src/boot.ts` 的 `transport.onMessage` 里，**每条消息进来就写**（在过滤之前——这是 bug，见"已知问题"）。

**保留多久**：`recentRaw(7)` 读最近 7 天。文件不删，但一般只用 7 天内的。

**为什么要有它**：distill 的原料。它只负责"发生了什么"，不判断重不重要。

---

### 2. episode（情节）

**文件**：`persona/memory/episodes/<scope>/2026-10-25-01.md`

- `<scope>` 是 `private-1234567890` 或 `group-631887317`
- `-01` 是同一天的第几条

**实现**：`src/memory/store.ts` 的 `saveEpisode()` / `nextEpisodeId()`

**内容**（带 frontmatter）：

```markdown
---
date: 2026-10-25
scope: private:1234567890
importance: 3
emotion: 困惑又有点被触动
lastRecalled: 1792923527588
title: 凌晨两点他失眠说想看我成长
---

快两点了他还没睡，说在学着怎么让我更好，又说想看我成长。我问他是不是失眠在看代码，
他说学的是计算机，四级又不考计算机。我让他把话说清楚，他说想要的是我。我有点接不住。
```

**关键字段**：

| 字段 | 作用 |
|---|---|
| `importance` | 1-10，参与召回打分 |
| `emotion` | 当时的情绪，召回时展示 |
| `lastRecalled` | 上次被想起来的时间，影响"新近度" |
| `title` | 一句话概括，召回时先看这个 |

**谁写它**：`src/memory/distill.ts` 的 `distill()`

---

### 3. fact（事实）

**文件**：`persona/people/<personId>/facts.md`

**实现**：`src/memory/facts.ts`

**格式**（纯 markdown，人能直接改）：

```markdown
# 关于这个人的事实

- 他四级基本没复习，对英语没兴趣，但坚持要考（2026-10-25，置信 0.95，公开）
- 他作息很乱，常到两点后，有一晚到了四点半（他自称平常睡得早），第二天还有课（2026-10-25，置信 0.9，私密）
- 他给我加了反思、记忆、总结几个功能（2026-10-25，置信 0.9，公开）｜我测试没啥问题，所以问问你感觉怎么样
```

**字段**：

```ts
interface PersonFact {
  text: string
  date: string
  confidence: number          // 0-1
  visibility: 'public' | 'private' | 'unsure'
  source?: string             // 他当时怎么说的（｜后面那段）
  lastConfirmed?: string      // 上次被确认的日期
}
```

**置信度会衰减**（`effectiveConfidence()`）：

```ts
base * Math.exp(-0.023 * days)
```

半衰期约 **30 天**。三个月不提，置信度从 1 掉到 0.12。

**为什么衰减**：长时间没确认的事，可能已经过时了（比如"他在学英语"——可能早放弃了）。

**黑名单**（`persona/people/<id>/deleted.jsonl`）：
用户删掉的事实记在这里，`isDeleted()` 阈值 0.7，防止 distill 又提炼回来。

---

### 4. insight（洞察）

**文件**：`persona/memory/insights.jsonl`

**实现**：`src/memory/store.ts` 的 `appendInsights()`

```json
{"id":"...","date":"2026-10-25","scope":"private:1234567890","text":"他嘴上说不学，行动上不落","evidence":["2026-10-25-01","2026-10-25-02"]}
```

**和 fact 的区别**：
- `fact` 是**具体的事**（"他四级没复习"）
- `insight` 是**从多件事里看出来的模式**（"他嘴上说不学，行动上不落"）

**`evidence`** 指向支撑这条洞察的 episode，可以回查。

---

### 5. open（待问 / 答应）

**文件**：`persona/people/<id>/open.md`

**实现**：`src/people/open.ts`

```markdown
# 还没问完 / 答应过的事

- [ ] 他平时爱听什么歌，我还没得到回答（2026-10-25）
- [ ] 他四级复习打算怎么开始（2026-10-25）
```

**用途**：让它在合适的时候接着问，或者兑现答应的事。

**`kind`**：
- `open` —— 普通的没问完
- `pending` —— "我还没把握，想确认一下"（口吻更软）

---

### 6. shared（共享）

不是单独一层文件，是个 **scope**。

任何 `scope: 'shared'` 的条目，私聊和群聊都看得见。

**用途**：跨会话的公共信息（比如"他养了只猫"——在群里和私聊都该记得）。

## 二、可见性：谁能看见什么

**实现**：`src/memory/recall.ts` 的 `visible()`

```ts
export function visible(scope: Scope, current: Scope): boolean {
  if (current.startsWith('private:')) {
    return scope === current || scope === 'shared'
  }
  return scope === 'shared' || scope === current
}
```

翻译成表格：

| 条目的 scope | 在私聊 A 里 | 在私聊 B 里 | 在群 1 里 | 在群 2 里 |
|---|---|---|---|---|
| `private:A` | ✅ | ❌ | ❌ | ❌ |
| `private:B` | ❌ | ✅ | ❌ | ❌ |
| `group:1` | ❌ | ❌ | ✅ | ❌ |
| `shared` | ✅ | ✅ | ✅ | ✅ |

**这是隐私边界**：A 跟你说的私事，B 问起来不能说。

## 三、召回：怎么决定注入哪些

**实现**：`src/memory/recall.ts` 的 `scoreOf()`

### 打分公式

```
score = recency × 0.5 + relevance × 3.0 + importance × 2.0
```

| 项 | 算法 | 权重 |
|---|---|---|
| **recency** | `exp(-lambda × days)` | 0.5 |
| **relevance** | bigram Jaccard 相似度 | **3.0**（最高） |
| **importance** | `importance / 10`，夹到 [0,1] | 2.0 |

**lambda 由重要性决定**（`lambdaOf()`）：

| 重要性 | lambda | 半衰期 |
|---|---|---|
| ≥ 8（高情绪） | 0.005 | **约 139 天** |
| ≥ 5（普通） | 0.02 | 约 35 天 |
| < 5（琐事） | 0.04 | 约 17 天 |

**含义**：重要的事忘得慢，琐事忘得快。

### 配置（`rules.yaml`）

```yaml
记忆:
  检索:
    取回条数: [5, 8]        # [事实, 情节]
    最低分: 1.2
    权重:
      新近: 0.5
      相关: 3
      重要: 2
```

### 注入 prompt 的样子

```
【关于他，我记得】
- 他四级基本没复习，对英语没兴趣，但坚持要考
- 他作息很乱，常到两点后，有一晚到了四点半（私事，对着别人别说）（他当时说：四点半，你忘记了？）

【我想起来的事】
- 2026-10-25｜凌晨两点他失眠说想看我成长（当时：困惑又有点被触动）
  快两点了他还没睡，说在学着怎么让我更好...

【我对他的一些看法】
- 他嘴上说不学，行动上不落

【还没问完 / 答应过的事】
- 他平时爱听什么歌，我还没得到回答
```

**注意**：私密事实会带 `（私事，对着别人别说）` 标签，这是给模型的隐私提示。

## 四、写入：什么时候记

### 每条消息 → raw

`src/boot.ts`：

```ts
transport.onMessage((m) => {
  ...
  appendRaw({ ts: m.at, scope: scopeOf(m.from), role: 'user', text: displayText })
  ...
})
```

**已知 bug**：`appendRaw` 在 `shouldDrop` **之前**（第 392 行 vs 387 行）。虽然已经把过滤提前了，但**群消息的 `m.senderId` 可能为空**，导致 raw 里没有发言人。

### 定时 → distill（提炼）

`src/scheduler/distiller.ts` 的 `shouldDistill()`：

```ts
if (turns.length >= 20) return true           // 攒够 20 条
const hours = (now - lastAt) / 3_600_000
return hours >= 24 && turns.length >= 4       // 或者隔了一天且有 4 条
```

**每 30 分钟检查一次**。

**distill 做的事**：
1. 把 raw 喂给模型，让它提炼
2. 产出：episodes / facts / insights / open / life
3. **并发保护**：`serialized('distill', ...)` 防止两个 distill 同时跑

### 反思 → self.md / life.md

`src/self/reflect.ts` 的 `reflectSelf()`，**每 12 小时一次**。

产出：
- `自述` → `self.md` 的「我是谁」
- `在想` → 「我最近在想」
- `生活[]` → `life.md`
- `特征` → 说话倾向 / 对陌生人 / 不喜欢

### 刷视频 → life.md

`src/outward/watch.ts`：

```ts
appendLife(today(), [`翻到个视频《...》，我想到：...`])
```

## 六、几条设计原则

### 1. 人能直接改

除了 `.jsonl` 和 `.json`，**所有记忆都是 markdown / yaml**。

你可以直接改 `facts.md`、`self.md`、`life.md`、`qzone-draft.md`——改完重启（或等热重载）就生效。

### 2. 每一层都有去重

| 层 | 去重方式 |
|---|---|
| `life.md` | `similarity > 0.5` 或 `sharedBigrams >= 长度/4` |
| `facts.md` | distill 里 `sim > 0.9` 判重，`0.45-0.9` 问模型 |
| `plays.md` | `similarity > 0.7` |
| `qzone-draft.md` | 同上（双重判据） |

### 3. 每条都有容量上限

| 文件 | 上限 |
|---|---|
| `life.md` | 40 条 |
| `facts.md` | 无上限（但置信度衰减会自然淘汰） |
| `plays.md` | 高分 60 条 / 低分 20 条 |
| `qzone-draft.md` | 5 条草稿 / 20 条已发 |
| `groups/<id>/members.json` | 最多 30 个群 |
| `session` | 40 轮 + 滚动摘要 |

### 4. 坏数据不整份作废

每个解析函数都有容错：
- `facts.md` 某一行坏了 → 跳过那一行
- `mood.yaml` 坏了 → 返回 null（当没心情）
- `groups.json` 坏了 → 重建空库
- `life.md` 有空行 → 忽略

## 七、已知问题

### 1. 字符相似度分不出语义

实测：

```
同义改写「他养了一只叫豆豆的猫」vs「他有一只猫叫豆豆」: sim = 0.231
不同事实「他喜欢猫」vs「他喜欢狗」:                  sim = 0.500
```

**同义改写的相似度反而更低**。所以：
- `facts` 的灰色地带（0.45-0.9）要问模型
- `life.md` 用「共同 bigram 数」辅助

### 2. `importance` 完全靠模型自己给

distill 时让模型给 1-10 分。**模型倾向于都给 5-7**，区分度不高。

**影响**：`lambdaOf()` 的三档（8/5/其他）实际很少触发第一档。

### 3. raw 不删

`persona/memory/raw/*.jsonl` 只增不减。一天 60 条消息就是 60 行，一年 2 万行。

**目前没影响**（distill 只读 7 天），但**迟早要归档**。

## 八、临时记忆（待做）

用户要求：**搜索结果进临时记忆**。

### 设计

```
persona/memory/temp/2026-10-26-搜XX.md
```

```markdown
---
at: 1793006824522
query: 什么是 SSR
source: brave
ttlDays: 7
---

## 结果
1. 【标题】https://...
   摘要...

## 抓的正文
...
```

### 和正式记忆的区别

| | 正式记忆 | 临时记忆 |
|---|---|---|
| 进 distill | ✅ 会被提炼成 facts | ❌ 不进 |
| 召回 | ✅ | ⚠️ 只在高相关时 |
| 过期 | 置信度衰减 | **7 天后直接删** |
| 注入 prompt | ✅ | 只在当轮 / 相关时 |

### 为什么分开

1. **搜索结果通常是别人的话**，不是"关于这个人的事实"
2. **会过期**（新闻一周就旧了）
3. **不进 distill** 就不会污染 facts

### 实现要点

- `saveTemp({ query, results, body })` → 写文件
- `loadTemp(query, limit)` → 按相似度取最近几条
- 启动时清理超过 TTL 的
- prompt 里作为单独一段注入：`【我查到的（可能过时）】`
