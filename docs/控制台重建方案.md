# 控制台重建方案

> 你提的 6 个痛点，我归成两类：
>
> **A. 找不到入口**（87 人点不进去、想建档没入口、名字改不了）
> **B. 看不全**（不知道他在哪些群、画像/印象/关系改不了）
>
> 加上一句"其实我不想管这么多人" —— 这句话最重要，它决定了设计方向。

---

## 一、根子上的问题：按「功能」分页

现在：

```
侧边栏：状态 / 记忆 / 自我 / 设置 / 工具
记忆页： [记忆] [核心] [群成员] [搜索]     ← 按功能分
```

**麻烦在于**：你脑子里想的是"**这个人**怎么回事"，但界面上得先想"我要看他的事实还是印象"，然后去不同的 tab。

**而且**：
- **人物只在「记忆」页的右上角一个下拉框里**
- **群成员在另一个 tab**
- **两边不通**

**企业级后台的做法是反过来**：**先选对象，再选看什么**。

```
人物（列表 → 详情）
  └ 详情页里用 TAB 分：概览 / 事实 / 经历 / 关系 / 画像 / 印象 / 待问
群组（列表 → 详情）
  └ 详情页里用 TAB 分：成员 / 设置 / 记忆
```

## 三、三个页面

### 页面 1：人物列表

**一眼要看到的信息**（企业级列表的四个要素）：

| 列 | 为什么 |
|---|---|
| **头像 + 名字** | 认人 |
| **在几个群** | 解决"不知道他在哪些群" |
| **关系（阶段 + 数值）** | 一眼看出熟不熟 |
| **记了多少条** | 判断"值不值得点进去" |
| **最近说话** | 判断"还活跃吗" |

**两个关键按钮**：

- **有档案的** → `[编辑]`
- **没档案的** → `[建档]`（解决"想建档没入口"）

**批量操作**（企业级必备）：
```
☐ 全选  [批量建档]  [批量删除]  [导出]
```

### 页面 2：人物详情

```
← 返回

  (欲)  欲辨已妄言              [改名]  [删除]
         qq:1234567890
         在群：631887317（群代肝）· 710344485（我是菜鸟）

┌──────────────────────────────────────────────┐
│ 概览 │ 事实 │ 经历 │ 关系 │ 画像 │ 印象 │ 待问 │ 原始 │
└──────────────────────────────────────────────┘

（下面内容随 TAB 切换，不跳页）
```

**TAB 的划分依据**：**一张表里放不下，但都属于同一个人**。

**每个 TAB 都能改**（解决"画像/印象/关系改不了"）：
- **画像**：文本框 + 保存
- **印象**：文本框 + 保存
- **关系**：4 个滑块（信任/亲密/好奇/依赖）+ 阶段预览
- **名字**：顶部 `[改名]`

### 页面 3：群组详情

```
群 631887317 · 52 人 · 认识 3 个     [刷新] [从快照恢复]

┌───────────┐
│ 成员 │ 设置 │
└───────────┘

[搜索成员]

头像  群名片        昵称        关系   记忆   操作
(群) 群代肝        欲辨已妄言   眼熟   7条    [查看]
(军) 军大获全胜。  —           —      0      [建档]
(万) 万九星        —           —      0      [建档]
```

**关键**：**群成员页直接能"查看"和"建档"**（解决"87 人点不进去"）。

## 四、和现在比，具体多了什么

| 之前 | 之后 |
|---|---|
| 人物在右上角下拉框 | **独立页面 + 可搜索可筛选的表格** |
| 群成员点不进去 | **群成员页每行有 `查看` / `建档`** |
| 画像/印象只能看 | **详情页 TAB 里能改** |
| 关系只能看 | **滑块调** |
| 名字被写坏改不回来 | **详情页顶部 `改名`** |
| 不知道某人在哪些群 | **列表的「群」列 + 详情页顶部** |
| 91 人混在一起 | **默认只显示有内容的，其余折叠** |
| 改个东西要跳好几个 tab | **一个详情页 TAB 切换** |

## 五、实施顺序（建议）

**分四步，每步都能独立用**：

### 第 1 步：骨架（半天）
- 侧边栏改成：**人物 / 群组 / 记忆 / 自我 / 设置 / 工具**
- 人物列表页（只读，能点进详情）
- 人物详情页（TAB 骨架，内容先复用现有的）

**做完就能**：从列表点进任何一个人的详情，不用再找下拉框。

### 第 2 步：能改（半天）
- 详情页：改名、改画像、改印象、改关系（滑块）
- 这些都是**新增 API**（`PUT /api/person`、`PUT /api/person/relation`）

**做完就能**：所有东西都能在控制台改，不用碰文件。

### 第 3 步：群组页（半天）
- 群组列表 → 群详情 → 成员列表带 `查看` / `建档`
- `建档` = 给这个人建一份空档案（`ensurePerson`）

**做完就能**：群成员页 91 人全部可操作。

### 第 4 步：企业级细节（一天）
- 批量操作（多选、批量建档、批量删除）
- 排序 / 筛选 / 搜索
- 折叠"没说过话的 87 人"
- 空状态、加载状态、错误提示

## 六、要不要现在就动

**你说"等我思考一下"，所以这篇只是方案，没动代码。**

两个可以考虑的点：

**1. 先做第 1 步能立刻改善**
人物列表 + 详情骨架，**不碰数据结构、不碰现有逻辑**，纯前端重构。风险很低。

**2. 或者等你想清楚"企业级"具体要什么样**
如果真要按企业后台的标准做（多租户、权限、审计日志），那就是另一个量级的事，值得先画个图。

**我倾向第 1 步先做** —— 因为它能立刻解决"87 人点不进去"和"找不到人"这两个最烦的。

## 七、关于 agenttree

你提到用 agenttree 做。**控制台重建适合用**，因为：

- **多文件**（`index.html` + `server.ts` + 可能新增组件）
- **可验收**（每个页面能截图验证）
- **有明确的树**：
  ```
  控制台重建
  ├── 1. 侧边栏 + 路由
  ├── 2. 人物列表页
  ├── 3. 人物详情页
  │   ├── 3.1 概览
  │   ├── 3.2 事实（复用）
  │   ├── 3.3 关系（新 API）
  │   └── 3.4 画像/印象（新 API）
  ├── 4. 群组列表页
  ├── 5. 群组详情页
  └── 6. 批量操作
  ```

**但先别急** —— 等你决定要不要按这个方向走，我再用 agenttree 拆任务树给你确认。
