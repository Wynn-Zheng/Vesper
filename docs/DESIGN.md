# Vesper 控制台设计规范

> 方向：**A+「精确带一点柔」**（参考 Linear 的克制 + 交互反馈）
> 一句话：靠**线、底色差、字重**分层；紫色只在激活态；动效只在 hover。
> 定稿：2026-10-29

---

## 1. 色彩

| 令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#08090A` | 页面底（暖调近黑，不是纯黑） |
| `--sunk` | `#0F1013` | 侧栏、比页面更暗的凹区 |
| `--panel` | `#16171C` | 卡片、面板 |
| `--panel2` | `#1E1F25` | 卡片内嵌、输入框、hover 提亮 |
| `--line` | `rgba(255,255,255,.06)` | 发丝边框（**所有分隔都靠它**） |
| `--line-2` | `rgba(255,255,255,.10)` | 需要强调的边框（按钮、输入框） |
| `--line-hover` | `rgba(255,255,255,.15)` | hover 时的边框 |
| `--text` | `#F7F8F8` | 主文字 |
| `--dim` | `#9CA3AF` | 次级文字 |
| `--dim2` | `#6B7280` | 说明、占位 |
| `--blue` | `#5E6AD2` | **唯一强调色**，主按钮 / 激活态 / 图表线 |
| `--green` `--red` `--yellow` | `#3FB950` `#F85149` `#D29922` | 状态色，只用于小面积（点、数字） |

规则：
- 紫色全屏占比 **< 5%**；永远不做大面积背景
- 一个屏幕最多 **一种** 强调色
- 不用彩色胶囊/色块做分类，用文字 + 细线

## 2. 间距

`4 / 8 / 12 / 16 / 24 / 32 / 40`（`--s1` ~ `--s7`）

**模块间距走专用令牌**（不是内边距，是"块与块之间"）：

| 令牌 | 值 | 用在哪 |
|---|---|---|
| `--gap-card` | **16** | 同层模块之间：卡片 → 卡片、区块 → 区块 |
| `--gap-group` | **24** | 分组之间：上一个分组的内容 → 下一个分组的标题 |
| `--gap-section` | **32** | 页面大分区（一个页面里明显不同的几块） |

**分组内部**（例如设置页「权限」分组里，白名单卡片 → @ 开关卡片）用 `--s3`（12），比模块间距紧一档，体现"它俩是一组"。

其余规则：

- 卡片内边距：14–16
- 卡片内部元素之间：8–12
- 页面左右：24
- **不出现非 4 倍数的值**（14 是唯一例外，仅用于卡片内边距）

**容器约定**：一个页面的内容容器如果是"一列模块"，就用 `display:flex;flex-direction:column;gap:var(--gap-card)`（自我页 `#self-body` 就是这么修的——之前是普通 block，卡片全贴在一起）。

**之前的问题**：仪表盘 14、自我 14、插件 16、成员 12、设置 12/24 混着来，
同一种"卡片挨卡片"在不同页面差 4px——肉眼能看出来但说不清哪里不对。
现在统一到 `--gap-card`。

## 3. 字号

`11 / 12 / 13 / 14 / 20 / 28`（`--fs-xs` ~ `--fs-2xl`）

| 场景 | 字号 | 字重 |
|---|---|---|
| 大数字 | 20–28 | 700 |
| 卡片标题 | 12.5–13 | 700 |
| 正文/列表 | 12.5–13 | 400 |
| 说明/次要 | 11–11.5 | 400 |
| 等宽（时间、代码） | 11–11.5 | 400 |

- 中文避免 `font-weight:500`（雅黑无此字重，浏览器会合成加粗导致重影），用 400 / 700
- 大标题加 `letter-spacing:-0.02em`

## 4. 圆角与阴影

- 圆角：**8 / 14 / 18**（`--r-sm` / `--r-md` / `--r-lg`），上限 18
- 阴影：**不用**（`--shadow:none`）。分层全靠边框和底色差

## 5. 组件

- **卡片**：`--panel` 底 + `--line` 边框 + `--r-md`，内边距 14/16
- **卡片 hover**：边框 → `--line-hover`，底色不变（不浮起、不投影）
- **按钮**
  - 默认：`--panel` 底 + `--line-2` 边框，hover 底提亮
  - 主操作：`--blue` 底 + 白字
  - 危险：透明底 + `--red` 字
- **输入框**：`--panel2` 底 + `--line-2` 边框，focus 边框 `--blue`（不发光）
- **表格**：行高 36–40，行间 1px `--line`，无斑马纹，hover 行底色 `--panel2`
- **标签**：11px，`--panel2` 底 + `--line` 边框 + 4px 圆角，不用彩色
- **状态点**：6px 圆点 + 文字，颜色只取状态色
- **图表**：单折线 1.8px，面积填充 `--blue` 10% **纯色**（禁止渐变），网格线 `rgba(255,255,255,.055)`

## 6. 布局

- 侧栏 200px 固定；主区内容左右 padding 24
- 页面骨架（从上到下）：
  1. **顶栏**：当前分组名 + 右侧全局状态
  2. **页头**：标题（19–20px）+ 一句说明 + 右侧操作
  3. **工具条**：搜索 / 筛选 / tab
  4. **内容**：栅格（12–16px 间距）
- 多列卡片必须等高（`align-items: stretch`）
- 长内容必须给 `min-width: 0`，禁止撑破容器

## 7. 滚动

- **不做可见滚动条**：一律隐藏（`scrollbar-width:none` + `::-webkit-scrollbar{display:none}`），内容仍可滚
- 已出现滚动条的地方也要隐藏，不留半截滑块
- **禁止嵌套滚动**：一屏只有一个滚动容器；抽屉/弹窗内部滚动时，背后的页面不要能滚
- 内容多优先分页/分组/折叠，而不是靠滚动条
- 横向滚动同样隐藏，只在表格确实放不下时用
- 滚动容器必须 `min-height:0`（flex 子项）或固定高度，否则 `overflow` 不生效
- **例外**：`textarea` 等输入控件天然可滚，不算嵌套，也不该被压缩高度

## 8. 动效

- 时长：**160ms**，`ease-out`（`cubic-bezier(.22,1,.36,1)`）
- 只做三类：hover 换底色/边框、展开收起、淡入
- **禁止**：弹跳、弹性、位移超过 2px 的动画、发光

## 9. 文案

- 不用感叹号、火焰、星星等情绪符号
- 状态用中性描述：「+12% 较上周」而不是「暴涨 12% 🔥」
- 空状态给一句功能说明 + 一个操作入口，不留纯空白

## 10. 禁忌清单

- ❌ 线性渐变 / 径向光晕 / 彩色投影
- ❌ 圆角 > 18、玻璃拟态、霓虹描边
- ❌ 同一屏出现两种以上饱和色
- ❌ emoji 当图标用（图标一律单色线性 SVG）
- ❌ 半像素字号、非 4 倍数间距
- ❌ 可见的滚动条（系统默认样式）、嵌套滚动
- ❌ 中文用 `font-weight:500`
- ❌ 大面积紫色/彩色背景

## 11. 插件页（四组结构）

```
插件
├── 接入平台      哪个应用的消息进来（QQ / 微信…）
│    每个平台下挂"实现"：NapCat 是 QQ 的一种实现
├── 内置能力      跟主程序一起发，不能卸
├── 工具插件      type: tool —— 注册成模型能调用的工具
└── 已安装        type: event / panel / transport，从本地装的
```

### 为什么平台在插件页里

NapCat 不是"一个开关"，是**QQ 这个平台的接入实现**。以后接微信/Telegram，
是往「接入平台」里加一行，不是加一个并列的插件 —— 所以分组的第一层是**平台**，
第二层才是实现。

### 卡片两种形态

- **平台卡**（整行宽）：平台名 + 状态 + 下面列实现（每个实现一行：名称/版本/连接状态/登录/WS/安装目录/心跳 + 重启·停止·配置）
- **能力卡 / 插件卡**（网格）：图标 + 名称 + 版本 + 类型标签 + 开关 + 描述 + 参数 + 底部操作

### 标签约定

| 标签 | 含义 | 颜色 |
|---|---|---|
| `内置` | 跟主程序一起发，不能卸 | 灰 |
| `工具` | 注册成模型能调用的工具 | 蓝 |
| `外部` | 从本地装的，能卸 | 灰 |
| `协议端` | 平台的一种接入实现 | 灰 |
| `已连接` | 实现当前是活的 | 绿 |
| `未连接` | 需要去处理 | 红 |

## 12. 插件契约

> 动手写插件看 `docs/写插件.md`；这里只讲契约。

### plugin.json

```json
{
  "id": "weather",
  "name": "天气",
  "version": "0.1.0",
  "type": "tool",
  "entry": "index.mjs",
  "description": "一句话说明它干什么",
  "configSchema": {
    "city": { "type": "string", "label": "默认城市", "default": "广州" }
  }
}
```

`type` 决定它在插件页哪一组、宿主给它什么能力：

| type | 能力 | 分组 |
|---|---|---|
| `tool` | `ctx.registerTool()` —— 注册成模型能调用的工具 | 工具插件 |
| `panel` | 提供前端面板（还没做） | 已安装 |
| `transport` | 平台接入实现（NapCat 这种，还没抽象完） | 接入平台 |
| `event` | 只 `ctx.on/emit`（默认，最弱） | 已安装 |

### 插件的 ctx

```js
export function activate(ctx) {
  ctx.log('...')                                  // 打日志（进 data/logs）
  ctx.config                                      // plugin.json 声明 + plugins.yaml 里的值
  ctx.dataDir                                     // 自己独占的数据目录
  ctx.on(event, handler) / ctx.emit(event, data)  // 事件
  ctx.registerTool({ name, description, parameters, run })   // 只有 type: tool 才有意义
}
export function deactivate(ctx) { ... }
```

**工具重名**：后注册的被忽略（先注册的赢），错误记进 `host.errors`。

### 权限

`plugin.json` 的 `permissions` 声明这个插件要什么：

| 权限 | 给了什么 | 没声明时 |
|---|---|---|
| `net` | `ctx.fetch(url, init)` | `ctx.fetch` 不存在（`undefined`） |
| `memory` | `ctx.readPersona(relPath)` —— 只能读 `persona/` 内，`..` 和绝对路径拒绝 | `ctx.readPersona` 不存在 |
| `message` | `ctx.send(target, text)` —— 走宿主的 transport，跟它自己发消息同一条路 | `ctx.send` 不存在 |
| `files` / `shell` | 还没接 | — |

**装之前会展示**：点「安装」→ 填路径 → 读 `plugin.json` → 弹窗列出名字/版本/类型/权限 → 你点「仍然安装」才复制文件。

**这是提示，不是沙箱。** 跟 VS Code（extension host 同权限）和 DSH/Cordis（vm 只限时，明确"协作式信任"）一样：

- 声明了才有 `ctx.fetch` 这种**便捷入口**
- 但挡不住插件直接写 `globalThis.fetch(...)` 或 `import('node:fs')`
- 真正的隔离要把插件丢进 Worker/子进程走 IPC，那会改插件写法 —— 这一版不做

**未接的**：`files` / `shell`。这两个风险明显更大（能读全盘、能执行任意命令），暂时不给。\n\n**`ctx.send` 的实际链路**：插件 → `ctx.send` → `consoleOpts.transport.send` → NapCat。通道没连时抛「NapCat 未连接」，插件自己 catch 处理。

## 13. 不该出现在设置页的东西

判断标准：**"改一次就很少再动"才是设置**。

| 内容 | 该在哪 | 为什么 |
|---|---|---|
| 模型 / API Key / 服务地址 | 设置 → 连接 | 一次配好 |
| 权限（黑白名单、必须 @） | 设置 → 权限 | 一次配好 |
| 数据目录 / 日志保留 | 设置 → 数据 | 一次配好 |
| 版本 / 更新 / 重启 | 设置 → 关于 | 运维入口 |
| 协议端（NapCat） | **插件 → 接入平台** | 它是外接的，不是设置项 |
| 备份 / 还原 | **设置 → 操作** | 是"做一件事"，不是"配一个值" |
| 健康检查 | **测试 → 工具连通性** | 是诊断，不是设置 |
| rules.yaml 原文 | 设置 → 高级（折叠） | 太底层，正常情况下用不到 |
