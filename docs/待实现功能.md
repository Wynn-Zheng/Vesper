翻了 NapCat 源码，有个扩展 action：

[`packages/napcat-onebot/action/extends/SendQzoneMsg.ts`](https://cdn.jsdelivr.net/gh/NapNeko/NapCatQQ@main/packages/napcat-onebot/action/extends/SendQzoneMsg.ts)

**它内部做的事**（源码里能看到）：
1. `uriToLocalFile` 把图片下载到临时目录
2. `uploadImageToQzone(base64)` 上传图
3. `publishQzoneMsg(content, richvals, ugcRight, targetUins)` 真发

### 我们要改的地方

```
src/channel/transport.ts   接口加一个可选的 sendQzone(msg, opts)
src/channel/onebot.ts      实现它：callAction('send_qzone_msg', {...})
src/outward/qzone.ts       新建：决定发什么、什么时候发

```

**注意 `ugc_right`**：我们 `rules.yaml` 里已经有 `外部.发空间.默认权限`，正好对应。

### 风险

- **发出去删不掉**（要手动去 QQ 空间删）
- **内容失控**：得有个"发之前先看一遍"的门（`需要确认: true` 已经配了）
- **频率**：不能一天发十条，得限

### 建议

**先做"草稿模式"**：它想发的时候，把内容塞进 `persona/qzone-draft.md`，你在控制台看到后点"发出去"。

比全自动安全，也能验证它写得好不好。

## 2. 上网搜索（成本中等，1-2 天）

### 三条路

| 方案 | 成本 | 稳定性 | 备注 |
|---|---|---|---|
| **A. SearXNG 自建** | 要一台机器/容器 | 中（会被人封） | 开源元搜索，聚合 Google/Bing 等 |
| **B. Brave Search API** | 免费额度（2000 次/月） | 高 | 官方 API，要注册 key |
| **C. 只抓固定几个站** | 最低 | 看目标站 | 比如只查 B站/知乎/维基 |

### 参考项目

- [agent-web-search](https://github.com/blueewhitee/agent-web-search)：SearXNG + fetch + extract + scrub + chunk + embed/rank，专为 AI agent 做的
- [SearXNG](https://github.com/searxng/searxng)：自建搜索，JSON 输出

### 我们要改的地方

```
src/outward/search.ts      新建：search(query) → [{title, url, snippet}]
src/outward/fetch.ts       新建：fetchPage(url) → 正文（去掉导航/广告）
src/tools/web.ts           新建：注册成工具给模型调
```

**关键**：**别让模型直接拼 URL 去抓**（SSRF 风险）。只能：
- 走搜索接口拿结果
- 抓搜索结果里出现的域名

### 风险

- **SSRF**：模型可能让它抓 `127.0.0.1` / 内网地址。必须白名单 + 禁止私有 IP
  （这块已经做过了：`src/plugins/net.ts` 的 `checkUrl()` 就是「协议 + 私有 IP + 域名白名单」三道闸，
  搜索工具直接复用，不用再写一遍）
- **内容安全**：抓到的东西可能有毒/违法，得过滤
- **成本**：一次搜索 + 抓 3 个页面 ≈ 几千 token

### 建议

**先做 B（Brave API）**——不用自己维护服务，免费额度对一个人用够了。

`search()` 只返回标题/URL/摘要，**不自动抓正文**。模型想看细节再调 `fetch(url)`，这样成本可控。

## 3. 执行代码（成本最高，风险最大）

### 参考项目

| 项目 | 做法 | 适合我们吗 |
|---|---|---|
| [agentic-sandbox](https://github.com/jmagly/agentic-sandbox) | KVM 隔离 VM，A2A 协议 | ❌ 太重 |
| [void-box](https://github.com/the-void-ia/void-box) | 容器 + 强制隔离边界 | ❌ 要 Docker |
| [Pydantic AI + E2B](https://pydantic.dev/articles/pydantic-ai-e2b-sandboxes) | 云端沙箱（E2B） | ⚠️ 要付费服务 |
| **Node 子进程 + 超时** | `child_process.spawn` + `timeout` + 无网络 | ✅ **最现实** |

### 最现实的方案：受限子进程

```ts
// src/tools/exec.ts
spawn('node', ['-e', code], {
  timeout: 3000,                    // 3 秒超时
  cwd: 'data/sandbox',              // 只能在这个目录读写
  env: {},                          // 清空环境变量（拿不到 API key）
  stdio: ['ignore', 'pipe', 'pipe'],
})
```

**限制**：
- **超时 3 秒**（防死循环）
- **清空 env**（防偷 key）
- **独立 cwd**（防读项目文件）
- **输出截断 2000 字**
- **只允许纯计算**（不能 import 文件系统）

### 但有个根本问题

**Node 子进程不是沙箱**。`node -e` 能：
- `require('fs')` 读写任意文件
- `require('child_process')` 起更多进程
- `fetch()` 联网

**真要隔离得上容器**（Docker / firejail），那就不是一个 Node 进程能解决的了。

### 我的建议：**不做**

理由：

1. **它是陪伴 bot，不是编程助手**。真需要算数，模型自己会算
2. **风险收益不成比例**：一个 QQ bot 有任意代码执行 = 一旦被提示注入就是 RCE
3. **已经有替代**：它能读自己的源码（`read_code`），问题定位够用了

**如果一定要做**，最低限度的安全底线：

```
- 只在私聊、只对 owner 开放
- 白名单 import（只允许 Math / JSON / 数组方法）
- 容器隔离（Docker + --network=none + --read-only）
- 每次执行前把代码给用户看，等确认
```

## 4. 看视频画面（结论：不做，字幕也拿不到）

### 已实测：字幕这条捷径走不通

`src/outward/bili.ts` 里本来就有 `subtitleOf()`，`detail()` 也会返回 `subtitle` 字段。
理论上"读字幕"比"抽帧看画面"便宜得多（字幕几千字 ≈ 2000 token，抽帧 10 次 ≈ 4000 token）。

**但实测 5 个热门视频，字幕全是 0 字**：

```
【2026全球总决赛】IG vs ...    简介 27 字，字幕 0 字 ✗
【IGN】10分，《影之刃零》评测    简介 114 字，字幕 0 字 ✗
双人抬棺                        简介 14 字，字幕 0 字 ✗
张麻子《鹅城FUNK》              简介 15 字，字幕 0 字 ✗
装X翻车...医学界翟天临          简介 11 字，字幕 0 字 ✗
```

**0/5 有字幕**。代码注释里那句"B站的 AI 字幕要登录才给，所以经常是空的"是对的。

### 真要做得付出什么

| 方案 | 成本 | 问题 |
|---|---|---|
| 登录 cookies 拿 AI 字幕 | 中 | 要维护登录态，掉线就没字幕 |
| `playurl` 拿视频流抽帧 | 高 | 下载几十 MB，视觉调用 4000+ token/个 |
| 只靠标题+简介 | **0** | 已经在用 |

### 建议：**保持现状**

**现在"只看标题和简介"不是缺陷，是最优解**：
- 免费
- 不碰版权
- 标题 + 简介 + UP主 + 分区，足够形成一个"看法"

**如果以后想要更多**，最划算的是**登录态拿字幕**（成本中等，收益最大），而不是抽帧。

## 一个原则

**能力越多，"它说自己能做什么"就越容易和实际不符**。

这轮 `test-honesty.ts` 41 项检查已经把"声明 vs 实现"自动化了。**每加一个能力，必须在那个测试里加对应断言**，否则过两周又会变成"它说能发空间但发不出去"。

具体做法：**先加测试（红），再实现（绿）**。
## 发布自动化（GitHub Actions）

**状态**：计划中，先手动发版

**目标**：打 tag 后自动打包并上传 Release，省掉"本地打包 → 手动戳浏览器传 101 MB"。

**计划的 workflow**：
- 触发：`on: push: tags: ['v*']`
- runner：`windows-latest`
- 步骤：checkout → setup-node → npm ci → `node scripts/package-electron.ts`
  → 裁 locales（只留 zh-CN/zh-TW/en-US）→ Compress-Archive → `softprops/action-gh-release` 上传

**暂缓的理由**：
1. 打包逻辑还在改（签名、NSIS、更新通道），CI 每次调试要等 10 分钟
2. 本地打包能"打完先试一下再发"，CI 没有这个中间检查点
3. 等发过两三个版本、打包流程稳定了再配

**注意**：公开仓库 Actions 免费不限时长。
