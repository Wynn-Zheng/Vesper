# 内在循环设计

> 记录「让它有自己的生活」这件事做到哪了、接下来想怎么做、为什么这么选。
> 最后更新：2026-10-25

---

## 一、现在是什么样

### 数据流

```
收到消息
  └→ 打分决定接不接
       └→ 组装 prompt（自我 + 记忆 + 关系 + 情绪）
            └→ 生成回复 → 分句发送

定时器
  ├→ 每 30 分钟：检查要不要整理记忆（攒够 20 轮 / 超 24 小时）
  ├→ 每 12 小时：自我反思（更新 self.md / life.md / will.json）
  ├→ 每 6 小时：刷视频（每天最多 2 个）
  └→ 每 30 分钟：检查要不要主动说话（阶段额度 + 意愿）
```

### 它的「自我」存在哪

| 文件 | 内容 | 谁写的 |
|---|---|---|
| `persona/self.md` | 我是谁 / 我能做什么 / 我最近在想 | 反思时它自己写 |
| `persona/life.md` | 它自己那边的事 | 反思 + 看完视频 |
| `persona/will.json` | 今天想不想说话 / 看视频 / 对人的印象 | 反思时它自己判断 |
| `persona/people/<id>/facts.md` | 记住了这个人什么 | 整理时提炼 |
| `persona/people/<id>/profile.md` | 他是什么样的人（客观） | 整理时生成 |
| `persona/people/<id>/impression.md` | **我对他的看法（主观）** | 反思时它自己写 |

### 已经交给它自己决定的

- 我叫什么（虽然还没取）
- 我是谁、我能做什么
- 我在想什么
- 看哪个视频、看完想到什么
- 今天想不想说话、想不想看视频
- 对每个人的印象

### 还没交给它的

- 记什么（现在按 `rules.yaml` 的规则提炼）
- 关系值怎么变（锚点规则）
- 隐私边界（硬编码的可见性判断）
- 什么时候必须回

## 二、下一步：让它在没人说话时也思考

### 问题

现在所有动作都是**被触发的**：

```
有消息 → 回话
到点了 → 整理 / 反思 / 主动 / 看视频
```

没有触发的时候，它什么都不做。

结果是：它想说的话，是「该说话了」逼出来的，不是「我想到了」冒出来的。

### 目标

加一个 **Thinker**：在没人说话的时候，它自己在想事情。

```
     ┌──────────────────────────────┐
     │       共享记忆（唯一通道）      │
     │  will.json / self.md         │
     │  thought.json / impression.md │
     └──────────────────────────────┘
          ▲                    ▲
          │ 写                 │ 读
     ┌─────────┐          ┌──────────┐
     │ Thinker │          │Responder │
     │ 空闲时想 │          │ 跟人说话  │
     └─────────┘          └──────────┘
```

**两者从不直接调用，只通过记忆通信。**

## 三、参考了什么

### [kiri](https://github.com/T-80BVVD/kiri)（AGPL-3.0，只参考设计）

> 一个常驻运转的数字生命内核——你不说话的时候，她也在自己思考。

它做对的事：

1. **连续的意识流（reverie）**——念头是一条线，上一条接续下一条，不是孤立的点
2. **承诺惦记**——说「回头我写 X」→ 记入目标 → 走神时自然想起 → 去做 → 做完回想
3. **LLM 是决策者**，不是文本生成器（输出 `{action, think, tool, args}`）
4. **内心系统**：情绪 PAD、动机、社交关系、生理节律、睡眠期记忆巩固

我们只借两点：**念头接续**、**承诺惦记**。

### [H6 — Continuous Inner Monologue](https://github.com/jlldavies/go4-llm-design-patterns/blob/main/patterns/H6-Continuous-Inner-Monologue.md)

论文级的设计模式（源自 [MIRROR, arXiv 2506.00430](https://arxiv.org/abs/2506.00430)）。四条硬规矩：

| 规矩 | 说明 | 我们现在 |
|---|---|---|
| **有界重建，不是追加** | Thinker 每轮**重建**叙事，不是往日志里追加。追加会让叙事无限长，最后被自己的历史噎死 | ❌ `life.md` 是追加，靠 40 条上限硬砍 |
| **必须有成本上限** | 没有 session / day 上限的 Thinker 是这个模式的标准烧钱失败 | ❌ 没有 |
| **明确落地规则（surface rule）** | 它想到的东西怎么让人知道：静默吸收 / 下一轮声明 / 主动说。选错了要么突兀要么看不见 | ⚠️ 现在是静默，但不确定有没有真的吸收 |
| **Thinker 只提议不动手** | 思考的结论不能直接产生副作用，要经过 Responder + 审批 | ✅ 现在没有副作用能力，天然安全 |

## 四、怎么实现

### 数据

```json
// persona/thought.json —— 覆盖，不追加
{
  "at": 1792928725393,
  "thought": "我在想……",
  "from": "上次想到的是……",
  "wantToTell": false,
  "aboutWhom": "qq-<QQ号>"
}
```

**关键：这是覆盖的**。`thought` 永远只有一条。

想透了就把它降级成 `impression`（对人的看法）或 `life`（自己的生活记录），然后清空。

### 循环

```
每 30-60 分钟醒一次
   ↓
有新对话吗？没有就跳过（不硬想）
   ↓
读：当前念头 + 上次想到哪 + 未完成的承诺 + 最近印象
   ↓
想：接上一句继续想，或者换一个话题
   ↓
判断：想透了没有？
   ├ 想透了 → 降级成 impression / life，清空 thought
   └ 没想透 → 覆盖 thought，记下 from
   ↓
判断：想跟他说吗？
   ├ 想 + 关系够 + 额度够 → 进 will.talk，等主动触发
   ├ 想 + 条件不够 → 留着，下次聊天时找机会提
   └ 不想 → 静默（只影响下次聊天时"你在想什么"那段）
```

### 成本

```
每次输入 ≈ 800 token（记忆 + 上次念头 + 自我）
每次输出 ≈ 150 token
每天最多 16 次（白天每小时 1 次）
没新对话就跳过 → 实际约 6-8 次/天

≈ 8k token/天 ≈ ¥0.01/天

硬上限：每天 20 次，超过就停
```

### 文件

```
src/self/thinker.ts     空闲思考循环
persona/thought.json    当前念头（覆盖）
```

## 五、风险

### 1. 想太多，变得做作

H6 文档自己列的失败模式：

> *Overthinking simple turns.* Thinker 一直跑，会往简单的话里塞用户没要的深度，回复变得做作。

**它现在已经在纠结「先信后疑」了**，如果每 30 分钟想一次，可能越想越拧巴。

**对策**：
- prompt 里写死「想不出新东西就停下来，不要硬想」
- 念头必须**收尾**，不能一直悬着
- 连续几天想同一件事 → 强制降级成 impression

### 2. 烧钱

**对策**：日上限 + 没新对话跳过。

### 3. Thinker 和 Responder 说两套话

> *Thinker-Responder divergence.* 独立会话会漂移：Thinker 得出一个结论，Responder 下一轮却说了相反的话。

**对策**：两者共享同一份 `self.md`，不各写各的。

### 4. 自我认知被重写

> Thinker 可以更新目标和信念，**不可以重写身份**。

**对策**：`self.md` 的「我是谁」只能由**反思**（12 小时一次）改，Thinker 不能碰。

## 七、还没想清楚的

1. **念头多久算「想透了」？**
   现在是让它自己判断。但模型可能倾向于「一直没想透」（显得深刻）。

2. **「想跟他说」的额度怎么定？**
   现在用 `will.talk` + 阶段额度。但念头是随时冒的，额度是按天算的，时间粒度不匹配。

3. **要不要让它有「情绪驱动的念头」？**
   比如心情差的时候想得更悲观。现在情绪（`mood.yaml`）和念头是两条独立的线。

4. **睡眠期巩固？**
   kiri 有「睡眠期记忆巩固」。我们现在只有定时反思。
