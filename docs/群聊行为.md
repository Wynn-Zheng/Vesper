# 群聊行为说明

> 这份文档回答一个具体问题：**它在群里什么时候会说话、什么时候不说话。**
> 2026-11 那次群聊审查（20 多轮）之后的行为契约，调参和排障都以它为准。
>
> 代码入口：准入在 `src/channel/onebot.ts`（`shouldHandle` / `isObserveOnly`），
> 决定在 `src/boot.ts`（`handle`），拼提示在 `src/loop/chat.ts` + `src/loop/prompt.ts`。

---

## 一、三档参与方式

在控制台「**设置 → 权限 → 群里必须 @ 它才回复**」里选，写 `rules.yaml` 的 `行为.群聊模式`：

> 它不在「自我 → 对话规则」页（那页是 26 项 schema 驱动的说话方式，不含群聊模式）。

| 档位 | 什么情况下回 |
|---|---|
| **只听** | 只有被 @、被叫名字、或引用它说过的话 |
| **熟人续话**（默认） | 上面三种，**加上**刚跟它说过话的人（2 分钟内） |
| **自己判断** | 不 @ 也放行，由内容打分决定（更活跃，也更可能插话） |

**这一项是唯一权威。**`persona/access.yaml` 里的 `成员.必须at` 是历史遗留字段，
现在只在模式缺失时兜底；控制台权限页那个「必须 @」开关是它的投影，保存时会同步模式。
（以前两边都读，出现过"权限页关了必须 @ 它还是不理"。）

## 二、什么叫"叫到它了"

按顺序判断，命中一条就算：

1. **@ 它**（`at` 段的 qq 等于 `self_id`）
2. **叫它名字**（`botNames`，取自 `self.md` / `rules.yaml`）
   - 词边界规则：名字后面必须跟空格、标点或呼语（在/呢/啊），
     否则不算 —— 「小鱼干」不触发「小鱼」，「满意」不触发「小满」
   - 单字名字更严：前后都要边界
3. **引用它说过的话**（`reply` 段指向它自己发过的消息）
   - 它发过的消息 id 只存在进程内存里（上限 300 条），**重启就空**。
     所以"引用别人的话"**不**判成"不是在跟它说" —— 那样重启后它会装没看见。

## 三、什么情况一定不回

| 情况 | 原因 |
|---|---|
| 明确 @ 了别人（不是它） | 那是在跟别人说话，不该抢答 |
| @全体成员 | 群公告，不是叫它 |
| 纯表情/纯语音（没有文字） | 通道层直接丢，不进任何统计 |
| 纯图片 | 「只听」「熟人续话」档不回；「自己判断」档会进打分，有概率接 |
| 「只听」档 + 没叫到 | 用户就是这么选的 |
| 触发群每分钟上限 | 见第五节 |
| 打分没过（「自己判断」档） | 日志里有「这次不接（N 分：理由）」 |

## 四、旁听（它看得见群里在聊什么）

群里没叫它的消息，会记进会话的**旁听区**（`Session.heard`），
在提示里渲染成一段「【群里刚才在聊】（没叫你，你只是在旁边看着）」。

- 只留最近 **12 条**、**2 小时**内
- **不进 turns、不进摘要、不参与复读检测** —— 否则模型会以为自己参与过那些对话
- 记录点：观察模式 / 打分没过 / 退避 / 偶尔不回 / 已读不回 / **限流丢弃** / **群每分钟上限** / **空回复且没叫它**
- **例外**：命中内容过滤（广告、刷屏）的消息**不记** —— 那类东西留在上下文里只会污染
- 同一个人刷屏时会被匀掉一些（按发送人限额），免得旁听只剩他一个人说话
- 合批时逐条按各自的发送人记，不会全挂到最后一个人头上

## 五、节奏控制

| 机制 | 配置 | 行为 |
|---|---|---|
| 群每分钟上限 | `行为.群每分钟上限` | 达到上限后**不生成**（省钱），包括「撤回」「看视频」这两条指令 |
| 连续对话窗口 | 固定 2 分钟 | 锚在**它最后一次真正发出回复**的时刻，不是"上次被 @"；同一人最多续 3 次，对方再 @ 才重置（否则一次 @ 会变成无限期必回） |
| 退避 | `行为.退避` | 连续决定不说话后放慢检查，攒够几条消息提前醒 |
| 偶尔不回 | `行为.偶尔不回概率` | 对「嗯」「哦」这类短消息随机不回 |
| 已读不回 | `行为.已读不回概率` | 有意义的话也可能决定不接（默认 0） |

## 六、合批（同一个人连发 / 几个人几乎同时说）

防抖窗口内的多条消息合成一轮处理：

- **逐条带名字**（`小红：…` / `小明：…`），同一个人连发也逐条带 ——
  只加一次前缀的话，第二句会被模型当成"它自己刚说过的"
- **这一批算谁说的 = 第一条叫到它的那条**：小明 @ 它问一句、小红紧跟着接一句，
  回的是小明、引用的是小明那条、关系也记在小明头上（不是最后说话的那个）
- 一批最多 20 条，攒满先冲一批
- 渲染进提示时有预算：**第一条一定保住**（那通常就是"@ 它 你看这个"），
  丢了几条会明写「（前面还有 N 条没贴出来）」

---

## 七、出站（它说出去的话）

- **不 @ 人**：CQ 码形态、`@全体成员`、`@昵称`（含标点后紧跟的）都会被去掉；
  只去掉 `@` 符号，名字留着（"@小明 刚才那句" → "小明 刚才那句"）
- **空回复不发**：模型返回空白就当沉默，不往群里发一条空气
- **一个字都没发出去时**（断线/被拒/内容被清空）：把历史里那条 assistant 撤掉，
  不让它"记得自己说过"

## 八、症状对照表

| 症状 | 先看这里 |
|---|---|
| @ 了它不理 | 日志搜「`@ 了我但被过滤`」，会打出具体原因；再确认「群聊总开关」和群白名单 |
| 它能看见但不接话 | 看日志「这次不接（N 分）」。分数低说明内容不值得接；想更活跃就切「自己判断」 |
| 它突然接了一句不搭的 | 看那条消息有没有 @ 别人（@别人不该接）；再看是不是「自己判断」档下打分误判 |
| 答非所问、不知道刚才聊了什么 | 确认旁听没被时间窗清掉（2 小时）；`data/sessions/group-*.json` 里看 `heard` |
| 改设置没反应 | 设置写的是文件，进程内快照靠 1.5 秒轮询更新；控制台的显示类接口已改成每次读文件 |
| 它以为自己说过一句用户没看到的话 | 检查日志「`这条一个字都没发出去，已从历史里撤掉`」有没有出现 |
