## 二、逐条对照

### ✅ 已有参考、值得整合的

#### 1. 多痕迹不合并（Hintzman 1986）→ **A-MEM**

**文献说的**：每经历一次就存一条独立痕迹，不合并成抽象图式。

**我们现在**：`life.md` / `plays.md` / `facts.md` **都在拼命去重**（sim > 0.5 就丢）。

**A-MEM 的做法**（摘要原文）：

> When a new memory is added, we generate a comprehensive note containing multiple structured attributes, including **contextual descriptions, keywords, and tags**. The system then analyzes historical memories to identify relevant connections, establishing **links** where meaningful similarities exist.

**关键**：**相似的不合并，而是建链接**。

**可借鉴的部分**：

```markdown
# life.md 改成
## 2026-10-25
- 翻到个视频《...》，我想到：包装再花哨也盖不住真本事

  → 关联：2026-10-20 那条「他吐槽过某个博主」也是这个意思
```

**但**：**我们不是图数据库**，建链接的成本高（要存关系、要遍历）。

**折中方案**：**只给 episode 加 `related` 字段**（存 1-3 个相关的 id），**不做全图**。

```yaml
---
date: 2026-10-25
scope: private:1234567890
importance: 5
emotion: 认同
related: [2026-10-20-02, 2026-10-18-01]
---
```

**收益**：召回时能"顺着链接带出一串"，比只靠相似度好。
**成本**：distill 时多一次判断（模型看已有 episode，挑 1-3 个相关的）。

**我的判断**：**值得做，但优先级中**（现在 9 条 episode，链接价值不明显；50 条以上才有用）。

---

#### 2. consolidate 用模型判断 → **Mem0**

**文献/项目说的**：Mem0 的流程是 **extract → consolidate**，consolidate 时**让模型决定** add / update / delete / noop。

**我们现在**：靠**字符相似度**判断（`sim > 0.9` 判重，`0.45-0.9` 问模型）。

**问题**（实测过）：

```
同义改写「他养了一只叫豆豆的猫」vs「他有一只猫叫豆豆」: sim = 0.231
不同事实「他喜欢猫」vs「他喜欢狗」:                  sim = 0.500
```

**同义改写的相似度反而更低** —— 所以 0.45 这个阈值**必然误判**。

**Mem0 的做法更好**：**每条新事实都让模型看一遍已有的**，输出四个动作之一。

**可借鉴的部分**：

```ts
// distill.ts 里，把"字符相似度筛 + 问模型"改成"直接问模型选动作"
const actions = await consolidateFacts(newFacts, existingFacts, llm)
// 返回 [{ action: 'add' | 'update' | 'delete' | 'noop', ... }]
```

**成本**：每次 distill 多一次模型调用（已有 9-30 条事实，一起塞进去）。

**收益**：**解决同义改写判不出来的问题**，这是目前最烦的一个。

**我的判断**：**值得做，优先级高**。但要注意成本——一次 distill 本来就有一次调用，多一次可接受。

---

#### 3. 人类审核写入 → **memorywire**

**项目说的**：

> no framework ships a **governance surface that lets a human review writes before they enter long-term storage**

**我们现在**：**已经有**（`persona/core-requests.md` + 控制台审批）。

**可以对齐的部分**：memorywire 定义的五种操作：

```
remember / recall / forget / merge / (审核)
```

**我们的对应**：

| memorywire | 我们 |
|---|---|
| remember | `appendFacts` / `saveEpisode` |
| recall | `recall()` |
| forget | `deleted.jsonl` |
| merge | distill 的去重 |
| **审核** | `core-requests.md` |

**我的判断**：**已经做了，不用改**。只是可以写进文档，说明我们的设计对齐了业界共识。

---

#### 4. 区分持久 vs 演变 → **RoMem**

**项目说的**（摘要原文，这句太准了）：

> most existing approaches model time as discrete metadata, either **sorting by recency (burying old-yet-permanent knowledge)**, simply **overwriting outdated facts**, or requiring an expensive LLM call at every ingestion step, leaving them **unable to distinguish persistent facts from evolving ones**.

**翻译**：现有做法要么按新近排序（**把"老的但永久"的知识埋掉**），要么直接覆盖过时事实——**分不出"持久"和"演变"**。

**这正是我们刚做的**：
- 幂律衰减 → 不让老知识被埋掉
- `major/normal` 分档 → 区分持久和演变

**RoMem 的技术方案**（连续相位旋转，把时间编码进向量）**我们用不上**（没向量库）。

**我的判断**：**方向已对齐，不用改**。可以记一笔"我们的 tier 分档和 RoMem 解决的问题是同一个"。

### ⚠️ 没找到参考、需要自己设计的

#### 5. 情绪加强巩固（McGaugh 2004）

**文献说的**：杏仁核在情绪唤起时加强海马对这段经历的巩固，**剂量相关**（越激动越牢）。

**我们现在**：

```ts
// recall.ts lambdaOf()
if (imp >= 8) return high       // 0.005（139 天）
if (imp >= 5) return normal     // 0.02（35 天）
return normal * 2               // 0.04（17 天）
```

**问题**：靠 `importance >= 8` 判断"高情绪"，但**实测模型打 importance 分区分度极低**（24 条经验全给 8 分）。

**而 `episode` 里有 `emotion` 字段**（"困惑又有点被触动"、"认同"），**这个才是真的情绪**。

**搜过的参考项目**：
- CogniPair（2506.03543）有 emotion 子 agent，但那是**多智能体数字孪生**，不是记忆衰减
- **没有找到"用情绪强度调衰减"的现成实现**

**所以需要自己设计** → 见第三节方案 A。

---

#### 6. 选择性重播（Kumaran 2016）

**文献说的**：

> 重播是**有选择的**：优先重播**意外的**、**有奖励的**、**还没学会的**

**我们现在**：`distill` 是**定时全量**——攒够 20 条就把这 20 条全喂给模型。

**搜过的项目**：
- **Contextual Experience Replay**（2506.06698）：是"web navigation 的任务经验重放"，**不是记忆提炼的筛选**
- **AgentHER**（2603.21357）：hindsight 重标定，场景不同
- **没有找到"记忆提炼时按意外度筛选"的现成实现**

**所以需要自己设计** → 见第三节方案 B。

---

#### 7. 遗忘是"取不出来"（Bjork）

**文献说的**：记忆有 **storage strength**（只增不减）和 **retrieval strength**（会掉）。遗忘是**取不出来**，不是**痕迹消失**。

**我们现在的偏差点**：`facts.md` 里置信度会**真的降到 0**（`exp(-0.023*days)`，一年后 0.0002），然后被 `eff >= 0.2` 过滤掉——**等于删了**。

**但按 Bjork 的说法**：**内容还在，只是取不出来**。

**实际影响**：
- 现在：一条一年没提的事实，**等于不存在**
- 按 Bjork：**内容留着，只是不进 prompt**，但**如果关键词精确匹配，还能捞出来**

**这是一条真正的设计分歧**，没有现成参考 → 见第三节方案 C。

## 三、需要你拍板的三个方案

### 方案 A：情绪强度调衰减

**问题**：现在用 `importance >= 8` 判高情绪，但 importance 不可靠；`emotion` 字段是真的情绪。

**设计**：

```ts
// recall.ts
function lambdaOfEpisode(e: Episode, decay?: Record<string, number>): number {
  const normal = decay?.['普通'] ?? 0.02
  const high = decay?.['高情绪'] ?? 0.005

  // 有情绪记录 + importance 也高 → 高情绪档
  if (e.emotion && e.importance >= 6) return high
  // 只有 importance 高但没有情绪记录 → 中档
  if (e.importance >= 8) return high
  // 其余
  return e.importance >= 5 ? normal : normal * 2
}
```

**核心改动**：**`emotion` 有值 + importance >= 6 就进高情绪档**（门槛从 8 降到 6，因为 emotion 提供了额外证据）。

**依据**：McGaugh 2004 的"剂量相关"——情绪越强越牢。`emotion` 有记录说明当时确实有情绪波动。

**代价**：几乎零（只改一个判断条件）。

**风险**：`emotion` 可能被模型滥用（每条都给个情绪）。要看现在的数据：

```
9 条 episode 里，有几条有 emotion？
```

**要我先查一下再决定吗？**

### 方案 B：distill 按"意外度"筛选

**问题**：现在攒够 20 条就全量提炼，不管这 20 条里多少是废话。

**设计**：

```ts
// 每条 raw 算一个"值得提炼"的分数
function worthDistilling(turn: RawTurn, existing: Episode[]): number {
  let score = 0
  // 1. 和已有记忆不相似 = 意外的（Kumaran 说的"意外"）
  const maxSim = Math.max(...existing.map(e => similarity(turn.text, e.title + e.body)), 0)
  score += (1 - maxSim) * 2
  // 2. 有情绪标记 = 情绪唤起（McGaugh）
  if (/\?|！|…|啊|呢|吧/.test(turn.text)) score += 0.5
  // 3. 长消息 = 信息量大
  score += Math.min(1, turn.text.length / 200)
  // 4. 提到约定/承诺的词 = 重要
  if (/答应|说好|一定|别忘|记得/.test(turn.text)) score += 2
  return score
}
```

**然后**：攒够 20 条时，**只提炼分数最高的 12 条**，剩下的留在 raw 里等下次。

**依据**：Kumaran 2016 说重播"优先挑意外的、有奖励的、还没学会的"。

**代价**：小（加一个打分函数）。

**风险**：
- 打分权重是**我拍的**，没数据支撑
- **可能筛掉真正重要的**（比如一句很平淡但信息量大的话）

**建议**：**先只加"约定/承诺"和"意外度"两个维度**，不要搞 4 个维度。

### 方案 C：遗忘不改内容，只改"取不取得出来"

**问题**：现在置信度衰减到 0 就等于删了。按 Bjork 的说法，**内容该留着**。

**设计**：

```ts
// 不改 facts.md 的内容（置信度存的是"记录时的置信度"，不随时间变）
// 只在召回时算"当前可及性"
const accessibility = effectiveConfidence(f, now)   // 这个会掉

// 召回时：
//   accessibility >= 0.2 → 正常注入
//   accessibility < 0.2  → 不进默认召回，但**关键词精确命中时仍可捞出来**
```

**具体做法**：

```ts
// recall() 里
const facts = allFacts
  .map(f => ({ f, acc: effectiveConfidence(f, now) }))
  // 旧逻辑：acc < 0.2 直接丢
  // 新逻辑：acc < 0.2 但关键词命中，仍然带出来（标注"很久没提了"）
  .filter(x => x.acc >= 0.2 || keywordHit(x.f.text, query))
```

**收益**：**符合"遗忘是取不出来"**，而且**一年后提到老事，它还能想起来**。

**代价**：小（改一个 filter）。

**风险**：
- `keywordHit` 要定义（用什么匹配？完整词？bigram？）
- 可能带出很多不相关的老事实

**建议**：**用 `similarity > 0.5` 作为"关键词命中"**（比默认召回门槛高，但比 0.2 的置信度门槛灵活）。
