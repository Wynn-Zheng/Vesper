## 🔴 严重（会返工）

### 1. 打包后 `persona/` 放哪 —— 这个坑最大

**问题**：

现在全项目用**相对路径** `persona/`、`data/`。开发时工作目录是项目根，没问题。

**打包成 exe 之后**：
- 程序装在 `C:\Program Files\QQbot\`（**只读**）
- `persona/` **不能写在那里**
- Electron 的标准做法是 `app.getPath('userData')` → `%APPDATA%/QQbot`

**而现有代码几十处用了 `persona/`**，全改成绝对路径工作量很大。

**解法（两条路）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 启动时 `process.chdir(userData)`** | 主进程一开始就把工作目录切到用户数据目录，**所有相对路径自动生效** | **一行改动**，但要求 Electron 在 spawn 后端前就 `chdir`，且后端所有路径都在 cwd 下 |
| **B. 加 `DATA_ROOT` 环境变量** | 所有路径改成 `join(DATA_ROOT, 'persona')` | 改动几十个文件，但更清晰 |

**建议 A**（先跑通），**B 作为以后的重构**。

**风险**：`process.chdir` 会影响进程内所有相对路径，**如果某处依赖 cwd = 项目根（比如读 `package.json`）会挂**。

### 2. Electron 和已有服务抢端口

**问题**：

如果你已经手动跑了 `npm start`（7788 被占），**Electron 又拉起一个** → **EADDRINUSE，后端起来就崩**。

**解法**：

```
Electron 启动
  → 先 GET http://127.0.0.1:7788/api/status
    ├─ 通（返回 200）→ 直接连它，不 spawn
    └─ 不通 → spawn 自己的后端
```

**而且要记住"这个后端是我拉的吗"** —— **只有我拉的，退出时才杀**（不然你手动开的会被杀掉）。

---

### 3. NapCat iframe 可能被路由挡

**问题**：

NapCat WebUI 是单页应用，`http://127.0.0.1:6099/` 返回的 HTML 里写着 `<link href="/webui/favicon.ico">` —— **说明它挂在 `/webui/` 路由下**。

**iframe 里加载根路径可能会 302**，而且**iframe 里的登录态和浏览器里是分开的**（要重新扫码）。

**解法**：

1. **先实测**：iframe 加载 `http://127.0.0.1:6099` 看会不会被 302、能不能显示二维码
2. **不行的话退化**：**不放 iframe，放一个"打开 NapCat WebUI"的按钮**（`shell.openExternal`）+ 显示连接状态
3. **注意**：如果 NapCat WebUI 要 token（`ca0337a4680d`），**iframe 里也要带上**

## 🟡 中等（会让人困惑）

### 4. 「能力」和「设置」会重叠

**问题**：

`电脑操作.enabled` 这个开关，**能力页有、设置页的"权限"也想有** → **用户不知道改哪**。

**解法（明确分工）**：

- **能力页** = "**这个能力是什么**、开没开、它的参数"（**面向理解**）
  - 例：看屏幕的开关、敏感词
- **设置页 → 权限** = "**跨能力的策略**"（**面向管理**）
  - 例："所有危险操作都要二次确认"、"哪些人能用危险能力"

**一个开关只出现在一个地方**。

### 5. 「自我」里有两个子栏是只读的

**问题**：

「我觉得有问题」（`issues.json`）和「代码地图」（`codemap.md`）**都是自动生成的，你改不了**。

放在"自我"里会让人以为能编辑。

**解法**：

**给这两个子栏打标**：标题旁加 `自动生成` 徽章，**编辑按钮灰掉**并提示"这个由它自己维护"。

### 6. 仪表盘和成员/自我页会「重复」

**问题**：

你说"仪表盘只放总览，细分的去对应栏"，但：

- **"关系分布"卡片** —— 成员页已经有了
- **"记忆统计"卡片** —— 自我页已经有了

**"总览"和"重复"的界限模糊。**

**解法**：

**仪表盘只放「健康度」指标**，不放内容统计：

| 放 | 不放 |
|---|---|
| 链路状态 | 几个人什么阶段 |
| 今日消息数 | 记忆有多少条 |
| Token 消耗 + 花费 | 具体事实内容 |
| **错误数（今天 warn/error 几条）** | |
| 最近一条活动 | |
| 运行时长 | |

**加一条规则**：**仪表盘上每个数字都可点击，跳到对应栏** —— 这样既是总览又不算重复。

### 7. 成员页「对话」列会读大量 raw

**问题**：

点开看历史对话 = 读 `raw/*.jsonl`。现在 262 条没事，**一年 2 万条就会卡**。

**解法**：**分页**（先读最近 50 条，滚到底再加载更多），**并且加时间筛选**（今天/7天/全部）。

### 8. 7 板块 × 6-7 子栏 = 可能点很多层

**问题**：

你要求"细分"，但**细分过头会变成"点 5 层才找到东西"**。

**解法（硬规定）**：

**最多两级**：板块 → 子栏。

**子栏内部不再分 tab**，只用卡片/列表/折叠。

## 🟢 轻微（注意一下）

### 9. 现有的「搜索」页没位置了

**问题**：

现在「记忆 → 搜索」能搜事实/经历/洞察。新结构七个板块里没有它。

**解法**：**放在仪表盘顶部当全局搜索框**（一个输入框，搜所有人/所有记忆）。

### 10. 「测试 → 试聊」和现有的「工具 → 试聊」重复

**问题**：

现在「工具 → 试聊」已经有了。

**解法**：**搬过去，删掉旧的**（不保留两个入口）。

### 11. 能力「测试一次」会真跑东西

**问题**：

点"测试一次"刷视频 → **真的会去 B 站调接口**，消耗配额。

**解法**：

- **测试时用最小的量**（刷视频只拿 1 个标题）
- **测试结果不写进记忆**（不要让它污染 `life.md`）

## 十二、参考项目

### [firefly DESKTOP-PACKAGING.md](https://gitlab.com/eaternity/firefly/-/blob/main/docs/build/DESKTOP-PACKAGING.md)（**最有用**）

**它的 Electron 架构**：

```
Electron Application
├── Main Process (Node.js)
│   - Window management
│   - **Python subprocess spawn**
│   - Application menu
├── Renderer Process (Chromium)
│   - React App (localhost:PORT)
└── Python Subprocess
    - FastAPI Server (**DESKTOP_MODE=true**)
```

**文件结构**：

```
desktop/
├── electron/
│   ├── main.js
│   ├── preload.js
│   ├── menu.js
│   └── **backend-manager.js**    ← 后端生命周期单独一个文件
├── assets/icon.png
```

**三个直接可抄的点**：

1. **`backend-manager.js` 单独管后端**（不塞进 `main.js`）
2. **`DESKTOP_MODE=true` 环境变量**（后端知道自己跑在桌面模式，可以改行为）
3. **"Self-contained (includes runtime)"** —— 打包时带上运行时

### SillyTavern V2/V3 角色卡（**"自我 → 角色卡"可以对齐**）

**V3 的字段**：

```json
{
  "spec": "chara_card_v3",
  "data": {
    "name": "名字",
    "description": "描述",
    "personality": "性格",
    "scenario": "场景",
    "first_mes": "开场白",
    "mes_example": "对话示例",
    "creator_notes": "作者备注",
    "system_prompt": "系统提示",
    "post_history_instructions": "后置指令",
    "character_book": { "entries": [] },
    "tags": [], "creator": "", "character_version": ""
  }
}
```

**对我们的价值**：

- **`self.md` 可以按这个组织**
- **能导出成 V3 角色卡**（和别人分享/导入 SillyTavern）
- **`character_book`** 对应我们的 `facts.md` + `core.md`

**不用照搬**（我们是聊天机器人不是扮演角色），**但字段划分值得借鉴**：

| 他们 | 我们 |
|---|---|
| `description` | `self.md` 的自述 |
| `personality` | `self.md` 的特征（说话倾向/对陌生人/喜欢/不喜欢） |
| `scenario` | `life.md`（它自己的生活） |
| `first_mes` | 第一次说话的开场 |
| `mes_example` | `learned/plays.md`（学说话） |
| `character_book` | `core.md` + `facts.md` |
| `system_prompt` | `prompt.ts` 拼的 |

### 🌟 [绘世启动器](https://raw.githubusercontent.com/licyk/SDNote/main/docs/sd_launcher/index.md)（秋葉aaaki + 喵喵hmkai）—— **最该学的**

**它解决的就是我们要解决的问题**：把一堆命令行、依赖、配置，包装成普通用户能用的东西。

**它的 8 个界面**：

| 界面 | 干什么 | 我们有对应吗 |
|---|---|---|
| **启动界面** | 一键启动、进度、状态 | ⚠️ 仪表盘有状态，**但没有"启动/停止"按钮** |
| **高级选项** | 启动参数（显卡、精度、端口） | ✅ 设置 |
| **疑难解答** | **诊断常见错误** | ❌ **完全没有** |
| **版本管理** | 内核版本切换/回滚 | ⚠️ 占位 |
| **模型管理** | 下载/移动/分类资源 | ⚠️ 我们没有模型文件，但有 `emoji/`、`learned/` |
| **小工具** | 零散工具 | ✅ 工具页 |
| **控制台** | 内嵌终端输出 | ✅ 日志页 |
| **设置** | 全局配置 | ✅ 设置 |

**三个我们该抄的**：

#### 1. 「疑难解答」→ 我们要做「体检」

**绘世的核心竞争力就是它**：新手最怕的是"点了没反应"，而它能把"为什么没反应"翻译成人话。

**我们的"体检"该查什么**：

| 检查项 | 绿灯 | 红灯时说什么 |
|---|---|---|
| **Node 版本** | ≥ 24 | "Node 太旧，去 nodejs.org 装 24" |
| **后端端口** | 7788 能被自己绑 | "7788 被别的程序占了（可能是另一个 QQbot 在跑）" |
| **DeepSeek API** | key 能调通（发一句"hi"，200ms） | "API key 不对 / 余额不足 / 网络不通" |
| **NapCat 连接** | `connected: true` | "NapCat 没连上：① 它开着吗 ② 反向 WS 配了吗 ③ 掉线了？" |
| **QQ 登录态** | 能拉到自己的 QQ 号 | "QQ 掉线了，用扫码重新登录" |
| **数据目录可写** | 能写一个临时文件 | "目录只读，换个位置或改权限" |
| **磁盘空间** | > 500 MB | "只剩 X MB，清理日志/截图" |
| **配置文件语法** | `rules.yaml` 能解析 | "第 N 行有语法错误：<原始报错>" |
| **群名单** | 每个群 > 1 人 | "群 631887317 的名单只有 1 人，点这里从快照恢复" |

**关键**：**每一项都能一键跳到「该怎么修」**（不是只报错）。

**这个功能比"版本更新"重要得多。**

#### 2. 「控制台」内嵌

它把服务的 stdout 直接显示在启动器里，**不用你去开终端看**。

**我们的日志页已经是这个思路**，但**缺"启动/停止/重启"按钮**（现在只能我自己杀进程）。

#### 3. `.app_path` 的思路

绘世会读一个 `.app_path` 文件，里面写着"内核在哪"。

**对应我们的"数据目录可配置"**：

```
启动器目录/.datapath      ← 内容是一行路径
                         ← 空 = 用默认（数据在启动器旁边）
```

**这样"先留按钮接口"就有具体形态了**：设置页显示这个文件的内容，**能改但先不开放编辑**。

## 十三、修正后的决定

| 项 | 原计划 | 改成 |
|---|---|---|
| **版本更新** | 真做 | **占位**（显示版本号 + git commit，按钮灰着） |
| **数据目录** | 可配置 | **占位**（显示路径 + 打开文件夹，**改不了**）+ 预留 `.datapath` 文件 |
| **群独立板块** | 考虑 | **不做**（群在成员页当筛选） |
| **打包路径** | 没想 | **`process.chdir(userData)`**（方案 A） |
| **端口冲突** | 没想 | **先探测 7788，通了就连，不通才 spawn** |
| **NapCat iframe** | 直接嵌 | **先实测 302/登录态，不行退化成按钮** |
| **仪表盘** | 9 张卡片 | **只放健康度指标，每个数字可点击跳转** |
| **能力 vs 设置** | 重叠 | **明确分工：能力=这个能力本身，设置=跨能力策略** |
| **只读子栏** | 没标 | **打「自动生成」徽章** |
| **搜索** | 没位置 | **仪表盘顶部全局搜索** |
| **试聊** | 两个入口 | **只留测试栏一个** |
| **🆕 体检/疑难解答** | **没有** | **加进设置页，当第一个子栏（这是最重要的功能）** |
| **🆕 启动/停止/重启按钮** | 没有 | **仪表盘和设置页都要有** |
