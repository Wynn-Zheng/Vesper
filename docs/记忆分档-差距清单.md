## 三、现有机制里能复用的

### 1. `lambdaOf()` 已有的三档衰减

```ts
// src/memory/recall.ts:34
export function lambdaOf(importance: number, decay?: Record<string, number>): number {
  const high = finiteOr(decay?.['高情绪'], 0.005)    // 139 天
  const normal = finiteOr(decay?.['普通'], 0.02)     // 35 天
  const imp = Number.isFinite(importance) ? Math.min(10, Math.max(0, importance)) : 5
  if (imp >= 8) return high
  if (imp >= 5) return normal
  return normal * 2                                   // 17 天
}
```

**这个骨架可以直接改成按档位**，不用重写：

```ts
function lambdaOf(tier: Tier, decay?): number {
  switch (tier) {
    case 'core':   return 0            // 不衰减
    case 'major':  return high         // 0.005
    case 'normal': return normal       // 0.02
    case 'temp':   return 0.3          // 极快
  }
}
```

### 2. `visible()` 的可见性矩阵可以照搬

```ts
// src/memory/recall.ts:16
export function visible(scope: Scope, current: Scope): boolean {
  if (current.startsWith('private:')) return scope === current || scope === 'shared'
  return scope === 'shared' || scope === current
}
```

**档位是「重要性」维度，`scope` 是「可见性」维度，两者正交**，互不干扰。

### 3. `scoreOf()` 的打分公式不用大改

```ts
// src/memory/recall.ts:77
score = recency * w.新近 + relevance * w.相关 + imp * w.重要
```

只是把 `imp`（importance/10）换成**档位给的权重**：

```ts
const TIER_WEIGHT = { core: 1.0, major: 0.8, normal: 0.5, temp: 0.2 }
```

### 4. `distill()` 已经有完整的提炼流程

```ts
// src/memory/distill.ts:147
export async function distill(opts: DistillOptions): Promise<DistillResult>
```

里面已经在处理：

```ts
// src/memory/distill.ts:189
for (const e of data.episodes ?? []) { ... }

// src/memory/distill.ts:214
for (const raw of data.facts ?? []) { ... }
```

**只要在 prompt 里让它多输出一个 `tier` 字段就行**，不用重写流程。

### 5. `appendLife` 的去重逻辑可以照搬给核心档的「申请」

```ts
// src/self/store.ts:239
export function appendLife(date: string, lines: string[]): void
```

里面的 `similarity + sharedBigrams` 双重判据，正好用来判断"这条申请是不是已经有过了"。

## 六、风险

### 🔴 高风险：`facts.md` 分段会碰老数据

现在 `facts.md` 是平铺列表：

```markdown
- 他四级没复习（2026-10-25，置信 0.95，公开）
- 他什么歌都听（2026-10-25，置信 0.9，私密）
```

改成分段：

```markdown
## 重要
- 他四级没复习（2026-10-25，置信 0.95，公开）

## 平常
- 他什么歌都听（2026-10-25，置信 0.9，私密）
```

**老文件没有 `##` 标题**，解析要能兼容：

```ts
// 有 "## 重要" 就用分段；没有就整份按 normal 处理
```

**这个必须写测试**，不然会丢数据。

### 🟡 中风险：模型给不准 tier

现在 `importance` 就给不准（全 5-7）。`tier` 也可能全给 `normal`。

**缓解**：
- prompt 里给**具体的判定标准**（不是"重不重要"，是"这件事下次还要不要记得"）
- **用"是不是约定/承诺/底线"这种客观条件**，比"重不重要"好判断

### 🟡 中风险：prompt 变长

核心档如果攒到 30 条，每条约 20 字 = 600 字。加上现有 1900 字，会到 2500 字。

**缓解**：核心档**限 30 条**，超了拒绝写入（让人删）。

### 🟢 低风险：临时档独立

全新模块，不碰老逻辑。就算坏了，也只是"搜索结果记不住"。

## 七、一个额外建议

**「它可以申请写核心」这个机制，建议和现有的 `qzone-draft.md` 用同一套模式**：

```
它写 → persona/core-requests.md
你看 → 控制台「记忆 → 核心」页
你点 → 批准（移到 core.md）/ 拒绝（删掉）
```

**好处**：
- 复用已验证的草稿流程（`src/outward/qzone.ts`）
- 你已经熟悉这个交互
- 申请和草稿在同一个地方审

**申请记录的格式**（照抄草稿的 markdown + frontmatter）：

```markdown
## 2026-10-26 23:50
- 为什么想记：他说以后别问他"你怎么了"
为什么这条想记成核心：这是他明确说过的边界，我要是忘了会反复踩。
```
