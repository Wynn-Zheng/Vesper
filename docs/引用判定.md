# 引用回复判定

> 为什么它该引的时候引、不该引的时候不引

## 背景

之前是概率：

```ts
if (addressed || hasQuestion) return true   // 被 @ 或问句 → 100% 引用
```

而实际配置是 `必须@: 是`，所以它回复的每一条都是"被 @ 的" → **每条都引用**，观感非常机械。

而且方向是反的：**被 @ 的时候指代已经零困难**（@ 已经指名了对象），**恰恰最不该引用**。

## 依据

Yajing Yang, *Quote-and-Reply in WeChat: A Conversation Analytic Study*,
Studies in Applied Linguistics & TESOL 25(1), 50–61, 2025.
（[ERIC EJ1478736](https://eric.ed.gov/?id=EJ1478736)）

分析了 7 段自然发生的微信对话，归纳出引用回复的 **3 类动机**：

| 类别 | 原文 | 对应场景 |
|---|---|---|
| **sequence-jumping** | responses to non-adjacent turns across temporal gaps | 回的是**不相邻的话轮**（中间隔着别的消息，或隔了很久） |
| **response facilitation** | enhance clarity and thematic coherence | **不引用就说不清**在回什么（澄清、指代不清、长消息只回一点） |
| **spotlighting prior text** | emphasizes specific messages for alignment or humor | 要**强调某一条**（认同、玩梗） |

论文总纲：引用是在 **mitigating challenges of multi-party chats and asynchronous interactions**
—— 解决"多人"和"异步"带来的指代困难。

**推论：引用是功能性的，不是礼貌性的。没有指代困难就不该引。**

## 判定

用打分，不是概率。每个信号对应一个具体的困难，累加到阈值才引。

### 加分

| 信号 | 分数 | 依据 |
|---|---|---|
| 这轮攒了 ≥2 条 | +2 | sequence-jumping |
| 有 ≥2 个人说话 | +2 | multi-party |
| 隔了 >60 秒才接上 | +1 | temporal gap |
| 对方那条 ≥60 字 | +2 | response facilitation |
| 回复里有澄清词 | **+5** | response facilitation（最强） |
| 回复里有强调词 | +2 | spotlighting |
| 情绪强度 ≥0.85 | +1 | spotlighting |

### 减分

| 信号 | 分数 | 依据 |
|---|---|---|
| 紧挨着上一条 | −2 | 指代零困难 |
| 被 @ 了 | −2 | @ 已经指明 |
| 私聊 | −3 | 只有两个人 |
| 60 秒内刚引过 | −3 | 上一轮已解决 |

**≥ 3 分才引用。**

### 两个特殊处理

**澄清时跳过 −2(紧挨着) 和 −2(被@)**

因为"它在澄清"本身就说明**它回的不是最新那句** —— 否则没什么可澄清的。
所以这两项扣分的前提不成立。澄清 +5 也足够单独触发。

**`often` 会降一级门槛**

配 `often` 时，2 分也引。这是给"我就是想让它多引一点"的人留的口子。

## 配置

```yaml
说话:
  引用频率: occasionally   # never 从不 / occasionally 按判定 / often 门槛降一级
  引用调试: false          # true = 日志里打印得分明细
```

开了调试之后日志长这样：

```
引用判定 4 分（+2 隔了3条，+2 2人穿插）→ 引用
引用判定 -4 分（+2 隔了2条，-2 紧挨着上一条，-2 被点名，-2 私聊）→ 不引
```

## 实测

`scripts/test-quote.ts` 覆盖 15 个场景，接在 `check-all` 里：

```
npm run check-all → 引用判定 通过 15 / 失败 0
```

想加信号或者调权重，改完跑这个，别把某类场景调坏。

## 已知取舍

**"对方发长消息"单独不够触发**（+2 −2 = 0）。

因为只有一条长消息、它紧跟着回 —— 对方知道你在回哪段。要**配合"隔了几条"**（长消息被别的消息淹了）才需要引用。

**情绪强度权重很低**（+1，且门槛 0.85）。

`mood.intensity` 经常常驻在 0.7~1.0，给高权重会变成"一直在引"。
