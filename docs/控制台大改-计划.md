## 一、目标

把现在的网页控制台改成 **Electron 桌面应用**，七个板块：

```
① 仪表盘   总览（只放总览，细分的去对应栏）
② 自我     角色卡：认知 / 准备做的事 / 备忘录 / 思考
③ 能力     每个能力的介绍 + 开关 + 基础参数
④ 成员     按人分行：来源 · 关系 · 记忆 · 对话 · 核心 · 日期
⑤ 日志     NapCat WebUI（二维码/连接）+ 项目日志
⑥ 设置     数据 / 服务 / 模型 / 权限 / 外观 / 关于
⑦ 测试     试聊 / 工具连通性 / 记忆检索（三个 tab）
```

**硬要求**：
- **断网也能启动**（不白屏、不 404）
- **Electron 自动拉起后端**（双击就能用）
- **细分，不要糊在一起**

## 三、技术方案

### Electron 怎么起后端

```
Electron 主进程
  ├─ 启动时：spawn node src/index.ts（子进程）
  ├─ 等 7788 就绪（轮询 /api/status，最多 20 秒）
  ├─ 就绪后：BrowserWindow.loadURL('http://127.0.0.1:7788/?token=…')
  ├─ 退出时：杀子进程
  └─ 崩溃时：自动重启（最多 3 次）
```

**断网也能启动**：
- **前端不用任何 CDN**（现在就是纯本地，字体用系统字体，图标用 emoji/内联 SVG）
- **后端只连 DeepSeek API**（断网时能起，只是不能回消息——**界面照常打开**）
- **NapCat iframe 连不上时显示占位**（"NapCat 没连上，点这里重试"）

**打包**：`electron-builder` → `.exe`（NSIS 安装包）

### 前端怎么改

**现在**：单个 `console/index.html`（2290 行，原生 JS）

**改法**：**不引入框架**（保持零依赖），但**拆成多个文件**：

```
console/
├── index.html          骨架
├── css/app.css         样式
└── js/
    ├── core.js         api() / el() / toast / 路由
    ├── dashboard.js
    ├── self.js
    ├── ability.js
    ├── member.js
    ├── log.js
    ├── settings.js
    └── test.js
```

**为什么拆**：2290 行单文件已经很难改（这次改坏过两次）。

## 七、风险

| 风险 | 影响 | 怎么防 |
|---|---|---|
| **改坏现有功能** | 控制台打不开 | 每阶段跑 `check-all` + 截图验证 |
| **Electron 打包体积大** | 装包 100+ MB | 可接受（你选了 Electron） |

| **前端拆文件引入 bug** | 某个页面白屏 | 拆的时候一个文件一个文件搬，每搬完测一次 |
| **`intent.md` 和 `open.md` 混淆** | 记忆混乱 | 明确区分：`open.md` = 等对方回答的，`intent.md` = 它自己要做的 |

## 八、还有三件事要你定

**1. "真正的软件更新（带版本号）"怎么做**

这个项目**没有发布渠道**。三个选择：

- **A. 用 git**：检查远端有没有新提交，一键 `git pull` + 重启。**最简单，但要求你有远端仓库**
- **B. 本地 zip**：你把新版本打包成 zip 放某个目录，它检测到就提示"有新版"
- **C. 先占位**：**只显示版本号**（`package.json` 的 version + git commit），**更新按钮先不做**

**2. 数据目录要不要可配置**

现在数据固定在 `persona/` 和 `data/`（相对项目目录）。

**成熟软件通常允许改**（"把数据存到 D 盘"）。**要不要做？**
