# 写插件

> 从零到一个能用的插件，30 分钟。契约细节见 `DESIGN.md` §12，这里只讲**怎么动手**。

## 1. 五分钟抄一个

复制 `plugins/weather/` 改名就行。最小可用的工具插件长这样：

```
plugins/天气/
├── plugin.json
└── index.mjs
```

**plugin.json**

```json
{
  "id": "my-weather",
  "name": "天气",
  "version": "0.1.0",
  "type": "tool",
  "entry": "index.mjs",
  "description": "查天气。它想知道今天热不热时用。",
  "author": "你的名字",
  "permissions": ["net"],
  "configSchema": {
    "city": { "type": "string", "label": "默认城市", "default": "广州", "hint": "模型没指定城市时用这个" }
  }
}
```

**index.mjs**

```js
export function activate(ctx) {
  ctx.log('天气插件起来了')

  ctx.registerTool({
    name: 'get_weather',
    description: '查某个城市现在的天气。想知道气温、下雨时用。',
    parameters: {
      type: 'object',
      properties: {
        city: { type: 'string', description: '城市名，不填用默认城市' },
      },
    },
    async run(args) {
      const city = String(args.city || ctx.config.city || '广州')
      const r = await ctx.fetch(`https://api.example.com/weather?city=${encodeURIComponent(city)}`)
      const j = await r.json()
      return `${city}现在 ${j.temp} 度，${j.desc}`
    },
  })
}

export function deactivate(ctx) {
  ctx.log('天气插件卸载了')
}
```

放进 `plugins/` → 控制台「插件 → 安装」填目录路径 → 确认权限 → 装好。

**验证**：卡片上点「测试」，直接跑一次工具，不用等模型去调。

## 2. plugin.json 的每个字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 小写字母/数字/连字符。**改了等于换一个插件** |
| `name` | ✅ | 显示名，可以是中文 |
| `version` | ✅ | 三段版本号 `1.2.3`，允许 `-beta` 后缀 |
| `entry` | ✅ | 入口文件，相对路径，必须 `.js` / `.mjs` / `.cjs` / `.ts` |
| `type` | 建议 | 见下表，不写就是 `event` |
| `description` | 建议 | 一句话说清"什么时候用它"，模型看得到 |
| `author` | 可选 | 装的时候会显示 |
| `permissions` | 按需 | 见 §4 |
| `configSchema` | 可选 | 有它控制台自动渲染表单；没有就退化成键值编辑器 |
| `minHostVersion` | 可选 | 宿主版本低于这个就拒绝加载 |

### type 决定什么

| type | 给什么能力 | 出现在插件页哪一组 |
|---|---|---|
| `tool` | `ctx.registerTool()`——注册成模型能调的工具 | **工具插件** |
| `event` | 只有 `ctx.on/emit`（默认，最弱） | 已安装 |
| `panel` | 前端面板（**还没实现**） | 已安装 |
| `transport` | 平台接入实现（**还没抽象完**） | 接入平台 |

**现在能用的只有 `tool` 和 `event`。**

### configSchema 支持的类型

```json
{
  "字符串": { "type": "string", "label": "显示名", "default": "默认值", "hint": "控件下面那行灰字" },
  "数字":   { "type": "number", "min": 0, "max": 100, "default": 42 },
  "开关":   { "type": "boolean", "default": true },
  "下拉":   { "type": "select", "options": ["宽松", "标准", "严格"], "default": "标准" }
}
```

用户在控制台改完，值写进 `persona/plugins.yaml`，**重载插件后生效**。

## 3. ctx 上有什么

```js
export function activate(ctx) {
  ctx.id          // 插件 id
  ctx.dataDir     // 这个插件独占的数据目录（宿主自动建）
  ctx.config      // configSchema 声明 + 用户填的值
  ctx.log(msg)    // 打日志，进 data/logs（控制台「日志」页能看到）
  ctx.on(ev, fn)  // 订阅事件
  ctx.emit(ev, d) // 发事件（只在自己插件内广播，不会串到别的插件）

  ctx.registerTool({ name, description, parameters, run })  // 任何 type 都能调

  // 定时器：**请用这里的，别直接用全局 setInterval**
  // 宿主在卸载/重载时会替你清掉。用全局的话，reload 之后旧任务还在跑
  // （它闭包着旧模块），重载几十次就多出几十份实例 —— 表现是"越用越卡"。
  const t = ctx.setInterval(fn, 1000)
  ctx.setTimeout(fn, 3000)
  ctx.clearInterval(t)

  // 下面三个按 permissions 给，没声明就是 undefined
  ctx.fetch(url, init)          // permissions: ["net"]
  ctx.readPersona(relPath)      // permissions: ["memory"]，只能读 persona/ 内
  ctx.send(target, text)        // permissions: ["message"]
}
```

> 用了全局定时器、开了文件句柄、连了 socket 的插件，请写 `deactivate(ctx)` 自己收尾。
> 宿主管不了插件自己创建的资源，只能保证"`ctx.*` 给的那些会被清掉"。

**判断能力在不在**：

```js
if (typeof ctx.fetch !== 'function') {
  ctx.log('没声明 net 权限，跳过联网')
  return
}
```

## 4. 权限

声明了才有，没声明就**是 undefined**（不是"调了会报错"，是根本没有这个函数）。

| 权限 | 给什么 | 实际能干什么 |
|---|---|---|
| `net` | `ctx.fetch` | 请求外部 API。**打不进内网**，见下面的「网络出口」 |
| `memory` | `ctx.readPersona(path)` | 读 `persona/` 下的记忆、档案、聊天记录；`..` 和绝对路径会被拒绝 |
| `message` | `ctx.send({kind,id}, text)` | 主动发消息，走宿主 transport（和它自己发消息同一条路） |
| `files` | `ctx.readFile` / `ctx.writeFile` | 只能读写**这个插件自己的 dataDir**；越界、junction 都会被拒 |

### 网络出口：`net` 不是裸 fetch

`ctx.fetch` 外面包了一层策略，挡的是 **SSRF**——插件把用户给的 URL 直接透传出去，
`192.168.1.1` 这种内网地址也能打，而机器人就住在你的内网里（路由器、NAS、摄像头）。

三道闸：

1. **协议**：只放 `http` / `https`。`file://`、`gopher://` 直接拒。
2. **地址**：解析出来的 IP 落在内网、回环、链路本地（`10.` `172.16-31.` `192.168.` `127.` `169.254.` `::1` `fc00::/7` …）→ 拒。这条是硬的。
3. **域名**：`rules.yaml` 的 `插件.网络` 里配白名单/黑名单。

```yaml
插件:
  网络:
    白名单: []          # 空 = 不限域名；填了就只放这些
                        # api.example.com / .example.com / *.example.com
    黑名单: []          # 优先于白名单
    允许内网: false     # 要调本地服务（ollama / TTS）才开
    超时: 20
    最多跳转: 5
```

重定向是宿主手动跟的，每一跳都重新过一遍检查——交给 `fetch` 自己跟的话，
一个公网 URL 302 到 `127.0.0.1` 就把上面全绕过了。

被拦时 `ctx.fetch` 抛错，日志里会有「插件 xxx 的网络请求被拦下：…」。

### 这是协作式信任，不是沙箱

跟 VS Code（扩展和编辑器同权限）、DSH/Cordis（vm 只限时）一样：

- 声明了才有 `ctx.fetch` 这种**便捷入口**，且入口本身带限制（网络禁内网、文件限项目内、命令有白名单）
- 但**挡不住**插件绕过入口直接写 `globalThis.fetch(...)` 或 `import('node:fs')` —— 插件代码和宿主跑在同一个进程、同一个运行时

所以：**只装你信得过的插件**。安装时控制台会把权限列出来让你确认。

要真正隔离，得把插件丢进 Worker 或子进程——那是另一个量级的改造，暂时没做。

## 5. 调试

### 改完怎么办

```
控制台 → 插件 → 你的插件卡片 → [重载]
```

不用重启服务。`deactivate` 会先跑，然后重新 `activate`。

### 看日志

```
控制台 → 日志 → 运行日志
```

`ctx.log()` 的内容会带插件前缀。

### 测试工具

卡片上的「测试」按钮直接跑 `run()`，结果弹窗显示：

```
[get_weather] 3ms

广州现在多云，24 度
```

**不用等模型去调**——这是最快的验证方式。

### 看报错

插件加载失败时，错误写进 `host.errors`，控制台列表里能看到，日志里也有：

```
[plugin:xxx] 载入插件失败：...
```

## 6. 常见坑

### plugin.json 带 BOM

Windows 记事本、PowerShell 的 `Set-Content -Encoding UTF8` 都会加 BOM。宿主读的时候已经去掉了（`\uFEFF`），但**别的工具可能不认**。

用 VS Code 保存时选「UTF-8」（不带 BOM）。

### entry 不能用绝对路径

```json
"entry": "index.mjs"        ✅
"entry": "../index.mjs"     ❌ 拒绝
"entry": "C:/x/index.mjs"   ❌ 拒绝
```

### 工具重名

两个插件都注册 `get_weather` → **后注册的被忽略**，先注册的赢。错误记进 `host.errors`。

给你的工具加前缀：

```
name: 'myweather_get'    → 不容易撞
```

### 把宿主搞崩

`activate` 里抛异常 → 这个插件加载失败，**其他插件不受影响**（宿主隔离了）。

但 `run()` 里的异常只会变成错误文本交给模型，**不会崩**——记得返回用户能看懂的话：

```js
async run(args) {
  try {
    ...
  } catch (e) {
    return '查天气失败了：' + e.message    // 模型会念给用户听
  }
}
```

### 不要在 activate 里做重活

`activate` 是同步调用的（`await` 了但阻塞加载）。要做初始化（拉配置、连服务）放到第一次 `run()` 里惰性做。

## 8. panel 类型：插件自带一个页面

除了 `tool`，还有 `panel`——插件提供一个页面，控制台里点「打开面板」用 iframe 打开。

### 三个文件

```
plugins/my-panel/
├── plugin.json      "type": "panel"
├── index.mjs        导出 activate + call
└── panel.html       页面本体
```

**panel.html** 是自己完整的 HTML（自己的样式、自己的脚本），在 iframe 里跑：

```html
<script>
  // ⚠ 面板跑在**沙箱 iframe** 里（不透明源）：
  //   - 拿不到主控制台的 window / document / cookie
  //   - 也拿不到控制台 token（URL 上不再拼 token 了）
  // 要数据请走 postMessage 桥，由宿主代发（它握有 token，但只代发到
  // 你自己的 /api/plugins/call，别的接口一律拒绝）。
  const pending = new Map()
  let seq = 0
  window.addEventListener('message', (ev) => {
    const d = ev.data
    if (!d || d.type !== 'vesper:result') return
    const p = pending.get(d.reqId)
    if (!p) return
    pending.delete(d.reqId)
    d.ok ? p.resolve(d.data) : p.reject(new Error(d.error || '调用失败'))
  })
  const call = (action, payload) =>
    new Promise((resolve, reject) => {
      const reqId = 'r' + ++seq
      pending.set(reqId, { resolve, reject })
      parent.postMessage({ type: 'vesper:call', reqId, action, payload }, '*')
    })

  // 用：const d = await call('ping', {})
</script>
```

**index.mjs** 导出 `call`：

```js
export async function call({ action, payload }) {
  if (action === 'ping') return { pong: true }
  throw new Error('未知 action：' + action)
}
```

### 注意

- iframe 的 CSP 是 `default-src 'self' 'unsafe-inline'`，**不能用外链 CDN**
- 页面里拿不到控制台的 `api()` / `el()` 这些函数，全部走 `call` 桥
- **不能直接 `fetch('/api/...')`**：面板是不透明源，没有 token，请求会被 401
- 出错只坏它那一块，不影响主控制台

> 为什么改成这样：以前 iframe 同时开了 `allow-scripts` 和 `allow-same-origin`，
> 而且 src 上拼着**完整控制台 token** —— 面板里的任何 JS（包括它引的第三方库）
> 都能卸插件、改模型、导数据，权限和手动操作控制台一样。
> 现在面板只能动这个插件自己的东西。老面板（自己从 URL 读 token）要按上面的
> 写法改成桥，否则调用会 401。

## 9. transport 类型：接入一个新平台

`transport` 是"消息从哪个应用进来"的实现（NapCat 就是 QQ 的那个）。

### 两个文件

```
plugins/my-transport/
├── plugin.json      "type": "transport", "platform": "weixin"
└── index.mjs        导出 activate + createTransport
```

**index.mjs**：

```js
export function createTransport(ctx) {
  return {
    name: 'my-transport',
    async start() { /* 连平台 */ },
    async stop() { /* 断开 */ },
    async send(target, text) {
      // target = { kind: 'private' | 'group', id: string }
      // 返回 { messageId } 或 undefined
    },
    isReady() { return true },
  }
}
```

`platform` 字段决定它归到「接入平台」的哪一组（`qq` / `weixin` / `telegram` / 随便什么）。

### 一个重要的限制

**要真正接管消息需要重启**。

原因：`boot()` 在启动时就把 transport 固定了，中途换通道要做状态迁移（会话、正在处理的队列），硬做容易出"换了一半"的状态。

所以现在的行为是：插件出现在「接入平台」列表里、能配置、能启停，但**要重启才生效**。界面上也写了这句，不装成能热插拔。

## 10. files 权限

### files

```js
// permissions: ["files"]
await ctx.readFile('x.json')     // 只能在自己的 dataDir 里
await ctx.writeFile('x.json', '...')
```

**边界**：路径必须落在**这个插件自己的 dataDir** 内。
`../` 怎么嵌套都逃不出去，junction / 符号链接也会被 realpath 拦下。

**很多时候不需要这个权限** —— `ctx.dataDir` 本来就能直接用 `node:fs` 读写。

### shell（已移除）

`shell` 权限**没有了**，`ctx.exec` 不存在。两个原因，都是实测出来的：

1. **它等于任意代码执行**。白名单里原来有 `node` / `python`，
   一句 `node -e "require('fs').rmSync(…)"` 就能做任何事。
2. **它在 Windows 上基本不能用**。剩下的命令（`echo` / `dir` / `type` /
   `ls` / `cat` / `grep` / `wc` / `head` / `tail` / `uniq` / `date`）在 Windows
   上大多不是可执行文件而是 cmd 内置命令，`execFile('echo')` 直接 ENOENT。
   而且当时 ENOENT 还被当成「成功、无输出」返回给插件。

要跑命令的插件，直接在自己的 `index.mjs` 里用 `node:child_process` ——
插件本来就是普通模块，宿主挡不住也没打算挡，`shell` 只是给了个
"看起来很安全其实不设防"的假象。

声明了 `shell` 的旧插件不会报错，但会收到一条提示（控制台插件页顶部），
里面写清了这个原因。

## 11. 更新源（plugins/index.json）

控制台「检查更新」读 `plugins/index.json`，把已装插件和这里的版本对比。

```json
{
  "plugins": [
    {
      "id": "weather",
      "name": "天气",
      "version": "0.3.0",
      "description": "查天气",
      "homepage": "https://github.com/你/仓库/tree/main/plugins/weather"
    }
  ]
}
```

- **只要 `id` + `version`**，其它字段都是给人看的
- 比本地版本大 → 卡片上显示「当前 → 最新」
- **不会自动下载**：只提示有新版，替换交给人工（自动替换正在运行的代码容易出半更新状态）
