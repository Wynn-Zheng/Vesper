## 1. 认知科学依据：真人记忆的七个事实

这七条决定了记忆系统该怎么设计，不是装饰。

### 1.1 记忆不是录像，是每次重新讲述

Bartlett（1932）发现人回忆是**重建**而非回放；Loftus 的系列实验证明每次回忆都会被当下污染。

**工程含义**：不要"检索原文 → 塞进上下文"。要"检索**锚点**（谁、什么时候、什么情绪、大概发生了什么）→ 让模型用**现在的自己**重新讲述"。

> 这是绝大多数记忆插件用起来"假"的根本原因——它们塞的是聊天记录，不是回忆。

### 1.2 遗忘是功能，不是 bug

Richards & Frankland（2017, *Neuron*）：遗忘是适应性机制，降低旧信息对当前决策的干扰。ZenBrain（arXiv:2604.23878）在 AI 上复现了这一点：轻度负载下 15 个记忆机制里 14 个消融都看不出差别；把遗忘率调到 0.25/天跑 60 天，9 个机制立刻变成关键（性能下降最高 93.7%）。

**工程含义**：不遗忘 = 记忆越多越蠢。必须有衰减、有淘汰。

### 1.3 情绪决定记忆强度

杏仁核在情绪唤醒时增强海马体编码——所以"吵架那天"比"普通周二"清楚。

**工程含义**：每条记忆需要**情绪权重**，高情绪衰减慢。

### 1.4 睡眠中巩固

Wilson & McNaughton（1994）：大鼠睡眠时海马体重放白天活动序列。睡眠把情景记忆压缩成语义记忆。

**工程含义**：反思就是它的"睡眠"。这一步做不好，前面全白搭。

### 1.5 间隔与遗忘曲线

Ebbinghaus + 间隔重复：回忆一次，衰减就变慢一次。

**工程含义**：每次召回要记账（`recalled_count`、`last_recalled`），召回过的衰减更慢。

### 1.6 记忆有"生活故事"的结构

McAdams 的叙事身份理论：自传体记忆不是流水账，是有主题、有转折的"我是谁"的故事。

**工程含义**：`self.md` 不该是属性列表，该是一段**可被改写的自述**。

### 1.7 关系记忆是双向的

RECALLbot（ACM CHI 2026）发现：人机关系里**不只是 bot 记住用户，用户也想知道 bot 自己的事**。双向披露显著提升关系感。

**工程含义**：它必须有"自己的记忆"可以讲给你听。单向记住你的 bot 是助理，不是人。

## 2. 这七条怎么落到设计里

| 认知事实 | 我们的做法 | 在哪 |
|---|---|---|
| 重构性记忆 | 召回输出"锚点"而非原文，让模型用当下人格重述 | 开发路线 §5.3 |
| 遗忘是功能 | 衰减公式 + 阈值淘汰（不删文件，只降权） | §5.5 |
| 情绪决定强度 | 三档 λ（普通 0.02 / 高情绪 0.005 / 锚点 0.001） | §5.5 |
| 睡眠巩固 | 反思（累计重要性触发 + 每日兜底） | §5.4 |
| 间隔重复 | 召回一次 `base × 1.15` | §5.5 |
| 叙事身份 | `self.md` 是可改写的自述，最多改 3 处 | §5.4 |
| 双向披露 | 它有自己的 `insights/`、`journal/`，能主动讲 | §5.4 |

**补充一个反例**（来自后续调研）：检索式记忆本质是查找，不是真记忆。它能按相似度泛化，但无法把经验固化成抽象规则，所以"越活越聪明"是做不到的——别对它抱这个期待。

- [Contextual Agentic Memory is a Memo, Not True Memory](https://arxiv.org/abs/2604.27707)（2026）

## 3. 硬件与本地模型

**本机**：Ultra 7 255HX（20 核）/ 32G 内存 / RTX 5060 Laptop **8G 显存** / Win11

| 角色 | 推荐模型 | 显存 | 说明 |
|---|---|---|---|
| 主脑 | **DeepSeek API** | 0 | 本地 8B 和 API 差距太大，别省这个 |
| 记忆嵌入 | `bge-m3` 或 `Qwen3-Embedding-0.6B` | 1～1.5G | 后期才用（<2000 条不需要向量） |
| 视觉理解 | `Qwen3-VL-8B` Q4 / `Qwen2.5-VL-7B` Q4 | ~6G | 看图片、表情包、截图 |
| 语音识别 | `faster-whisper large-v3` / `SenseVoice-Small` | 2～3G | 听语音 |
| 语音合成 | `CosyVoice2-0.5B`（快）/ `GPT-SoVITS`（像） | 2～5G | 发语音条 |
| 小脑/判断 | `Qwen3-4B` Q4 | ~3G | 判断要不要插话、情绪分类 |
| 画图（可选） | `Flux.1-schnell` Q4 / `SDXL-Turbo` | 8G 勉强 | 想要"画给你看"再上 |

**一个必须知道的坑**：RTX 5060 是 Blackwell 架构（sm_120），老版本 PyTorch / llama.cpp 会报 `no kernel image is available`。必须用 **CUDA 12.8+ 的 PyTorch** 或最新版 llama.cpp / Ollama。装之前先看版本号。

**用法**：模型不要常驻。按需加载（Ollama 会自动卸载闲置模型），或写个小调度器：收到语音才拉 ASR，要发语音才拉 TTS。

## 4. 退路：QQ 官方机器人

如果小号路线出问题（封号、协议端不稳定），切官方通道。

### 4.1 能做 / 不能做

| 能力 | 支持 | 说明 |
|---|---|---|
| 单聊收发文字 | ✅ | 被动消息有效期 60 分钟，每条可回复 4 次 |
| 群聊 @ 触发 | ✅ | 群主可在手机 QQ 开"接收全量消息""主动推送""撤回成员消息" |
| 主动发消息 | ✅ | 个人认证 1000 条/用户/天，20 条/分钟 |
| 发图片 / 文件 | ✅ | 富媒体，先上传拿 `file_info` |
| 发语音 | ✅（待验证样式） | 富媒体 `file_type=3`，需 SILK 编码，显示为语音条还是文件需实测 |
| 收语音 | ✅ | 收到的是 SILK，需转码成 wav |
| 撤回自己消息 | ✅ | 2 分钟内 |
| 加好友 / 看朋友圈 / 发空间 | ❌ | 平台不支持 |
| 给陌生人发消息 | ❌ | 只能给互动过的用户或"开发体验用户" |
| 公开被添加 | ❌（个人主体） | 不能公开上架，只能自己加群、自己私聊 |

### 4.2 个人主体的三条硬限制

1. 机器人不能公开上架，只有**你自己**和「开发设置」里加的**开发体验用户**能私聊它
2. 只能加进**你自己是群主/管理员**的群
3. 机器人有身份标识，对方知道这是 bot

> 对"我和它聊天"这个场景没影响。想扩到朋友，得注册企业/个体户主体。

### 4.3 接入要点（平台侧）

1. <https://q.qq.com/qqbot/openclaw/login.html> 用手机 QQ 登录 → 创建机器人（立刻成功）
2. 进 <https://q.qq.com/#/app/bot> 补主体认证（个人实名即可）
3. 记下 **AppID** 和 **AppSecret**（在「开发设置」）
4. 在「开发设置 → 开发体验用户」里加上自己的 QQ 号
5. 快捷创建通道会自动生成机器人，头像昵称都能改

> 具体到代码怎么接，等真要走这条线时再查 SDK；上面的能力边界短期不会变。

## 5. 服务器与内存

### 5.1 2C2G 的真实情况

| 组件 | 内存 |
|---|---|
| Linux QQ + NapCat | 800MB～1.5GB |
| 自研 bot（Node） | ~200～400MB |
| 系统 | ~300MB |
| **合计** | **1.3～2.2GB** |

**结论：全塞 2G 会 OOM，必须加 swap，而且会卡。**

三个选择：

1. **NapCat 留本机，bot 上云**（推荐）：本机常开，2C2G 只跑一个 Node 进程，很轻松
2. **全塞 2C2G + 4G swap**：能跑，但响应慢 1～3 秒
3. **升到 2C4G**：多花几十块，最省心

### 5.2 上云时的 swap 与守护

```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

systemd 单元见《开发路线》§9.2。
