# 扩展点：工具（function-calling）

> 现在是**留口子**状态：结构全部到位，但一个工具都没实现。
> 以后要加工具时，照这份文档做就行，调用链（boot → chat → send）不用动。

## 现在的状态

```
tools/types.ts       定义 Tool / ToolCall / ToolContext / ToolResult
tools/registry.ts    注册表，默认空；有 run() 和错误兜底
llm/types.ts         LlmOptions.tools、LlmResult.toolCalls、ChatMessage.toolCalls
llm/deepseek.ts      请求体带 tools、响应解析 tool_calls
loop/chat.ts         generateReply 里留了工具循环的接口点
```

**当前行为**：注册表是空的 → `opts.tools` 是 undefined → `chat()` 不传 tools → 模型不会返回 `tool_calls` → 走的还是原来那条路。

所以现在是**零运行时开销**的。

## 加一个工具要做的四步

### 1. 实现 Tool 接口

```ts
// src/tools/remind.ts
import type { Tool } from './types.ts'

export const remindTool: Tool = {
  name: 'remind',
  description: '他说"提醒我"的时候用。给定时间点和内容，到点会主动找他。',
  parameters: {
    type: 'object',
    properties: {
      when: { type: 'string', description: 'ISO 时间，如 2026-10-26T08:00:00+08:00' },
      what: { type: 'string', description: '提醒什么' },
    },
    required: ['when', 'what'],
  },
  async run(args, ctx) {
    // ctx.personId / ctx.scope / ctx.now 都能用
    return `好，${args.when} 提醒你${args.what}`
  },
}
```

### 2. 在 index.ts 注册

```ts
import { tools } from './tools/registry.ts'
import { remindTool } from './tools/remind.ts'

tools.register(remindTool)
```

### 3. 把注册表传给 generateReply

```ts
// src/index.ts
const reply = (m, rules) => generateReply(m, { rules, llm, tools })
```

### 4. 在 chat.ts 里补工具循环

`generateReply` 里已经留了这个位置：

```ts
if (res.toolCalls?.length) {
  warn('模型要求调工具，但工具循环还没实现', ...)
}
```

把它换成：

```ts
let msgs = messages
let result = res
for (let round = 0; round < 3 && result.toolCalls?.length; round++) {
  // 1. 把模型的 tool_calls 作为 assistant 消息记下
  msgs = [...msgs, { role: 'assistant', content: result.text, toolCalls: result.toolCalls }]

  // 2. 逐个执行
  for (const call of result.toolCalls) {
    const r = await opts.tools!.run(call.name, call.args, { personId, scope, now: new Date() })
    msgs = [...msgs, { role: 'tool', content: r.content, toolCallId: call.id }]
  }

  // 3. 再问一次
  result = await chat(msgs, { ...opts.llm, tools: specs })
}
```

**最多 3 轮**——防止它反复调工具绕圈。

## 三条原则

1. **工具执行失败不要抛**。`registry.run()` 已经把异常转成错误文本交给模型，让它自己决定怎么圆场。
2. **工具不能绕过权限**。工具里要做的事（发消息、改文件）都得再过一遍 `checkAccess` 之类。
3. **工具描述要写"什么时候用"，不是"能干什么"**。模型是靠 description 判断该不该调的。

## 为什么现在不做

工具的价值在于"能操作外部世界"。当前场景是**陪聊**，它要做的事（记忆、关系、主动消息）都在内部完成了，不需要工具调用来绕一圈。

真正需要工具的是这些场景：

- **提醒**（"明天提醒我"）— 需要定时任务 + 持久化
- **查东西**（天气、搜索）— 需要外部 API
- **发图片/表情** — 需要媒体处理

等这三个里有一个真的要做时，再按上面四步接。
